# 분할 프로토콜 구현 요청서 (Claude Code 작업 지시서)

## 0. 이 문서의 목적

CIC-IDS2017(정제판, CNS2022 기준) 데이터셋에 대해 **그룹 기반·요일 내 시간순 3분할 + LOAO 후처리** 파이프라인을 구현한다. 이 산출물은 이후 LightGBM 학습·확률 보정·유보 밴드 실험(3~7단계)의 유일한 입력 데이터가 되므로, 정확성과 재현성이 최우선이다.

이 문서는 새 대화(Claude Code 세션)에 그대로 전달할 것을 전제로 작성했다. 배경 설명, 요구사항, 검증 기준, 명시적 비목표까지 포함한다.

---

## 1. 배경 (왜 이런 설계인가 — 구현자가 임의로 단순화하지 않도록)

1-1. CICIDS2017은 요일별로 공격 유형이 배타적으로 배치되어 있다 (월=정상만, 화=무차별대입, 수=DoS/Heartbleed, 목=웹공격/Infiltration, 금=봇넷/PortScan/DDoS). 전체 5일을 하나의 시간축으로 보고 앞뒤로 자르면 목·금 전용 공격군이 학습에서 통째로 사라지는 의도치 않은 LOAO가 발생한다. **따라서 분할은 요일 내부에서 수행한다.**

1-2. 같은 공격 스크립트의 반복 실행으로 거의 동일한 피처 벡터를 가진 근사 중복 플로우가 다수 존재한다. 이들이 학습/평가에 무작위로 흩어지면 모델 확신도가 인위적으로 극단화되고, 그 여파로 이후 실험의 유보 밴드가 비어버린다. **따라서 개별 플로우가 아니라 공격 세션 근사 그룹 단위로 분할한다.**

1-3. LOAO(leave-one-attack-out)는 분할과 별개의 축이다. 특정 공격 레이블만 제거해야 하며, 해당 요일의 정상 트래픽이나 다른 공격군까지 같이 빠지면 안 된다.

이 세 가지 전제를 위반하는 단순화(예: 무작위 `train_test_split`, 전체 데이터 일괄 시간 분할, 요일 단위 LOAO)는 **허용되지 않는다.**

| 항목 | 내용 |

| 데이터셋 | CIC-IDS2017, CNS2022(Liu, Engelen et al.) 정제판 |

## 3. 요구 산출물

3-1. **그룹 인덱스 테이블** (parquet): `group_id, day, attack_label, rep_time, n_flows_in_group, split, original_split`

3-2. **전체 플로우 테이블** (parquet): 원본 전체 피처 컬럼 + `group_id`, `split` 컬럼 추가

3-3. **분할 요약 리포트** (CSV 또는 markdown 테이블): `(day, attack_label)`별 그룹 수·플로우 수 × `split` 피벗 테이블

3-4. **검증 로그** (텍스트/JSON): 6장의 검증 항목 각각의 pass/fail과 수치

3-5. **재현용 실행 스크립트/config**: 파라미터(버킷 크기, 분할 비율, LOAO 대상 리스트, 랜덤 시드)를 코드 상수가 아니라 config 파일 또는 CLI 인자로 분리

---

## 4. 파이프라인 요구사항 (단계별)

**4-1. 로드 및 병합**
요일별 CSV를 로드하고 `day` 컬럼(파일 출처)을 부여해 병합한다. 이 단계에서는 정렬·분할을 수행하지 않는다.

**4-2. 그룹 키 생성**
`group_id = hash(src_ip, dst_ip, attack_label, floor(timestamp / BUCKET_SEC))`. `BUCKET_SEC` 기본값 300초, config로 조정 가능해야 한다. BENIGN 레이블도 동일 규칙 적용(자연히 세분화됨).

**4-3. 그룹 대표 시각 산출**
`group_id`로 groupby하여 `rep_time = min(timestamp)`인 축소 테이블을 별도로 생성한다. 이후 정렬·분할 판단은 반드시 이 축소 테이블에서 수행하고, 원본 대용량 테이블은 마지막에 join만 한다 (연산량 절감이 목적이므로 이 순서를 바꾸지 말 것).

**4-4. 요일×공격레이블 단위 커트라인 계산**
축소 테이블을 `(day, attack_label)`로 그룹화 → 그룹 내 `rep_time` 기준 정렬 → 그룹 개수 기준 인덱스 분할(비율 기본값 train 60 / calib 20 / test 20, config로 조정 가능).

- 그룹 수가 임계치(기본 10, config 조정 가능) 미만인 레이블은 3분할에서 제외하고 전량 `test`로 배정. 이 목록을 리포트에 별도로 표시할 것.

**4-5. split 라벨 기록**
그룹 인덱스 테이블에 `split` 컬럼 확정. 이 시점까지 원본 플로우 테이블은 미수정.

**4-6. 원본 테이블에 join**
`group_id` 기준 left join으로 `split` 컬럼을 원본 플로우 테이블에 부여한다.

**4-7. LOAO 마스크 후처리**
- 입력: 배제 대상 공격 레이블 리스트(config)
- 로직: `attack_label ∈ 대상 리스트 AND split ∈ {train, calib}` 인 행의 `split`을 `test`로 덮어쓴다.
- `original_split` 컬럼에 원래 값을 보존한다(다른 LOAO 조합 재실행 시 원복 가능하도록).
- 이 로직은 **함수로 분리**하여, 대상 리스트만 바꿔 여러 번 재실행할 수 있어야 한다(전체 파이프라인 재계산 불필요).

**4-8. 저장**
3장에 명시한 산출물을 parquet/CSV로 저장.

## 5. 파라미터화 요구사항

아래는 반드시 하드코딩이 아닌 config(YAML/JSON) 또는 CLI 인자로 노출한다.

- `bucket_seconds` (기본 300)
- `split_ratios` (train/calib/test, 기본 0.6/0.2/0.2)
- `min_group_count_for_split` (기본 10)
- `loao_target_labels` (리스트, 기본 빈 리스트 = LOAO 미적용)
- `random_seed`
- 입출력 경로 전체

---

## 6. 검증 스크립트 요구사항 (필수, 파이프라인의 일부로 자동 실행)

6-1. `train`과 `test`에 동시에 등장하는 `group_id`가 0건인지 assert. (calib-test, train-calib도 동일하게 확인)

6-2. calib 세트가 어떤 학습 코드 경로에서도 `fit()`/`train()`에 전달되지 않는지 — 이건 코드 리뷰 수준 확인이므로 검증 스크립트에는 "calib split 데이터가 train 산출 모델 학습에 사용된 흔적(중복 인덱스 등)이 없는지"를 데이터 레벨에서 재확인하는 assert로 대체한다.

6-3. `(day, attack_label, split)` 피벗 테이블을 생성해 특정 레이블이 한 split에 100% 쏠려 있는 경우를 경고로 출력.

6-4. LOAO 적용 후: 대상 레이블이 `train`에 0건인지, 같은 요일의 다른 레이블·BENIGN 행 수가 LOAO 적용 전과 동일한지 assert.

6-5. 모든 항목은 pass/fail과 함께 수치를 로그로 남기고, 하나라도 fail이면 파이프라인이 비영시 종료 코드로 실패해야 한다(후속 단계가 잘못된 산출물로 조용히 진행되는 것을 방지).

---

## 7. 명시적 비목표 (구현자가 임의로 추가하지 말 것)

- 무작위 `train_test_split` 사용 금지
- 요일 단위 통째 배제(LOAO를 요일 삭제로 구현) 금지
- 피처 스케일링/정규화/인코딩 — 이 단계의 범위 아님(LightGBM 학습 단계에서 처리)
- 피처 누수 컬럼(Flow ID, IP, Timestamp, Destination Port) 제거 — 이 단계에서는 **컬럼을 남겨둔다**. 제거는 별도 전처리 단계(1단계 후반)의 책임이며, 분할 판단 자체에는 IP/timestamp가 필요하므로 이 스크립트 내부에서는 유지해야 한다. 최종 학습 입력 생성 시점에만 제거.
- 모델 학습, 확률 보정, 밴드 설계 — 3~7단계 범위이며 이 작업의 범위 아님

## 8. 완료 기준 (Acceptance Criteria)

- [ ] 3장의 5개 산출물이 모두 생성됨
- [ ] 6장의 5개 검증 항목이 모두 자동 실행되고 로그로 남음
- [ ] 6-1, 6-4가 실제로 pass함 (fail 시 원인 리포트와 함께 파이프라인 중단)
- [ ] `loao_target_labels`를 바꿔 재실행했을 때 그룹 인덱스 재계산 없이 LOAO 후처리 함수만 재실행되어 결과가 갱신됨 (4-7 요구사항 확인)
- [ ] 그룹 수 10 미만 레이블 목록이 리포트에 명시적으로 표시됨
- [ ] 모든 파라미터가 config/CLI로 노출되어 있고 코드 내 하드코딩된 값이 없음

## 9. 참고 — 후속 단계와의 연결

이 산출물(그룹 인덱스 테이블 + 플로우 테이블)은 3단계(LightGBM 다중 시드 학습), 4단계(확률 보정), 6단계(LOAO 배제 공격군 신뢰도 히스토그램)의 유일한 입력이다. `split` 컬럼 값이 여기서 틀리면 이후 모든 신뢰도·ECE·Brier score·risk-coverage curve 수치가 무효가 되므로, 6장 검증을 절대 생략하지 말 것.
