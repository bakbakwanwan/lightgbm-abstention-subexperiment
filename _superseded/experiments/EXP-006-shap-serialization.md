## 1. 질문

에스컬레이션된 플로우에 대해 TreeSHAP 기여도를 산출하고,
이를 2차 계층(프롬프트 기반 개별 판정)이 소비할 수 있는 형식으로 직렬화할 수 있는가.
그 비용은 실시간 경로에서 감당 가능한가.

## 2. 개념적 제약 (변경 금지)

1. **SHAP는 보정 전 마진(raw score)을 설명한다.** 보정 후 확률에 대한 기여도가 아니다.
   이 사실을 산출물 문서와 논문에 명시한다. 혼동하면 개념 오류가 된다.
2. **프롬프트에는 "예측 기여 특징"으로 전달한다.** 인과적 근거나 판정 이유로 서술하지 않는다
   (`docs/glossary.md` D절, 폐기 표현).
3. **환류 범위는 신뢰도 보정과 임계값 조정까지다.** 재라벨링 경로는 열지 않는다
   (design-constraints B-9).
4. **TreeSHAP은 에스컬레이션된 소수 플로우에만 적용한다.** 전량 적용하지 않으므로 비용 문제가 없다.
   이것이 LightGBM을 선택한 두 근거 중 하나(저비용 정확한 기여도)와 직결된다.

## 3. 입력

- 선행 산출물: `results/EXP-004/`에서 확정된 에스컬레이션 대상 플로우 집합
- 모델: EXP-002에서 학습된 모델(seed 42 대표 1개. 이 실험은 분포가 아니라 형식·비용을 본다)
- 설정 파일: `configs/exp/EXP-006.yaml`

### SHAP 설정

- **interventional 방식**을 쓰고 배경 데이터셋을 명시적으로 지정한다.
  배경 데이터는 `train`의 정상 트래픽에서 층화 표본추출하며, 표본 크기와 seed를 기록한다.
  배경 설정을 기록하지 않으면 기여도 수치가 재현되지 않는다.
- `tree_path_dependent` 방식과의 차이는 이 실험 범위가 아니다. 하나를 고정하고 기록한다.

## 4. 산출물 스키마

`results/EXP-006/metrics.json`

```json
{
  "exp_id": "EXP-006",
  "git_commit": "",
  "seed": 42,
  "shap_method": "interventional",
  "background_spec": {"source": "train_benign", "n_samples": null, "seed": null},
  "n_escalated_flows": null,
  "latency": {
    "shap_per_flow_ms_p50": null,
    "shap_per_flow_ms_p95": null,
    "shap_per_flow_ms_p99": null,
    "flows_per_second": null
  },
  "serialization": {
    "top_k": null,
    "mean_token_count": null,
    "max_token_count": null
  },
  "notes": ""
}
```

- 지연은 평균이 아니라 **p50/p95/p99와 초당 처리 플로우 수**로 보고한다(로드맵 L절).
  평균만 보고하면 꼬리 지연이 숨는다.
- `flows_per_second`는 EXP-004의 `verification_budget`을 실측값으로 대체할 수 있는
  첫 번째 근거가 된다. 다만 2차 계층 LLM 호출 비용은 여기 포함되지 않으므로 상한이 아니다.

추가 산출물: `serialization_format.md` — 2차 계층 프롬프트에 넣을 직렬화 포맷 명세와 실제 예시 3건.
이 문서가 이 실험의 **주 산출물**이며, `metrics.json`보다 중요하다.

## 5. 성공 / 실패 판정 기준 ← 실행 전에 작성, 이후 수정 금지

- **성공:** 에스컬레이션 대상 전량에 대해 SHAP 산출이 완료되고,
  `shap_per_flow_ms_p99`가 100ms 미만이며, 직렬화 포맷 명세와 예시 3건이 작성된 경우.
  → 3차 계층 착수 전 1차 계층 인터페이스가 확정된다.

- **성공 (조건부):** p99가 100ms를 넘지만 `flows_per_second`가 EXP-004 곡선상
  현실적 에스컬레이션 비율을 감당하는 경우.
  → 진행하되 지연 수치를 논문에 그대로 명시하고, "실시간" 표현을 이 수치로 한정 정의한다
  (로드맵 A-4: 검증 없이 "실시간"을 쓰지 않는다).

- **실패:** 직렬화된 기여도가 토큰 예산을 초과해 2차 계층 프롬프트에 담기지 않는 경우.
  → `top_k`를 줄여 재시도하되, 몇 개까지 줄여야 담기는지를 기록한다.
  `top_k`가 3 미만까지 내려가야 한다면 SHAP 전달 자체의 유용성을 재검토한다.

- **판정 불가 (측정 자체가 무효):**
  - 배경 데이터셋 설정이 기록되지 않은 경우. 재현 불가이므로 폐기.
  - SHAP 기여도가 보정 후 확률에 대한 것으로 잘못 계산·서술된 경우. 폐기 후 재작성.
