## 1. 질문

LOAO로 학습·보정 양쪽에서 완전히 배제한 공격군의 샘플은,
보정 후 확률 분포에서 어느 구간에 놓이는가.

## 2. 왜 이 실험이 분기점인가

배제 공격군이 **낮은 확률(정상 확신) 구간에 쏠리면** 유보 게이트가 이들을 잡지 못한다.
2차 계층이 검증 기회조차 얻지 못하므로 RQ2가 성립하지 않는다.
이 경우 중심축을 "신뢰도 기반 선택적 검증"에서 "신뢰도 + OOD 스코어 기반 선택적 검증"으로
수정해야 한다.

1. **소개글·초록의 중심축 문장은 이 결과가 나오기 전에 확정하지 않는다.**
2. `ADR-001`이 이 실험 ID를 조건부로 참조하고 있다.
3. 로드맵 C-1에서 지적한 대로, CNS2022 정제판 채택이 이 결과를 부정적 방향
   (라벨 노이즈가 줄어 분류가 쉬워지고 밴드가 더 비는 방향)으로 이끌 가능성이 있음을 인지하고 진행한다.

## 3. 입력

- 데이터셋: EXP-002와 동일 피처 집합, 동일 학습 설정
- 보정법: EXP-002의 `selected_calibration` 고정
- seed: EXP-002와 동일한 5개
- 설정 파일: `configs/exp/EXP-003.yaml`
- 선행 산출물: `results/EXP-002/metrics.json`, `predictions.parquet`

### 배제 공격군 선정

3~4개로 고정한다(로드맵 A-5 범위 고정). 선정 시 다음을 참고 입력으로 쓴다.

1. `split_summary_report.csv`의 `below_min_group_count` 레이블 18개 목록.
   이들은 전량 `test`로 배정되어 **이미 학습에서 배제된 상태**다(로드맵 D-8). DDoS가 대표적이다.
   따라서 별도 LOAO 지정 없이도 배제 공격군으로 기능하며, 이 사실을 반드시 기록한다.
2. 위 목록에 없으면서 샘플 수가 충분한 공격군에서 별도 LOAO 대상을 선정한다.
   재라벨링으로 샘플이 줄어든 희소 공격군(Web Attack, Infiltration, Heartbleed)은
   히스토그램의 통계적 의미가 약하므로 단독 근거로 삼지 않는다(로드맵 C-1).
3. **대표 공격군을 미리 확정하지 않는다**(로드맵 D-4). 위 두 입력을 본 뒤 이 스펙의 5절에 확정 기록한다.

### 배제 방식

- 대상 공격군을 `train`과 `calib` **양쪽 모두**에서 제거한다.
  보정 단계 누수가 가장 놓치기 쉬운 지점이다(design-constraints A-5).
- 요일 단위 통째 배제로 구현하지 않는다(로드맵 D-7). 같은 요일의 타 레이블·BENIGN 행 수는
  LOAO 이전과 동일해야 한다.
- 기존 `--loao-only` 경로를 재사용한다. 그룹 재계산 없이 실행 가능함이 이미 확인되었다(로드맵 D-8).

## 4. 산출물 스키마

`results/EXP-003/metrics.json`

```json
{
  "exp_id": "EXP-003",
  "git_commit": "",
  "seeds": [],
  "calibration": "",
  "held_out_attacks": [],
  "per_attack": {
    "<attack_label>": {
      "n_samples": null,
      "prob_histogram": [],
      "prob_cdf_quartiles": {"q25": null, "q50": null, "q75": null},
      "mass_below_0_1": null,
      "mass_0_1_to_0_9": null,
      "mass_above_0_9": null,
      "already_excluded_by_group_count": null
    }
  },
  "known_attack_reference": {
    "mass_below_0_1": null,
    "mass_0_1_to_0_9": null,
    "mass_above_0_9": null
  },
  "notes": ""
}
```

- `prob_histogram`: 20구간 등간격 빈도.
- `known_attack_reference`: 배제되지 않은 공격군의 동일 통계. 대조군이 없으면 배제군 분포를 해석할 수 없다.
- `already_excluded_by_group_count`: 해당 레이블이 `below_min_group_count`로 이미 test 전량 배정된 것인지 표시.
- 모든 값은 시드 5개의 평균과 표준편차를 함께 기록한다.

추가 산출물: `figures/heldout_prob_histogram_{attack}.png`
(배제군과 기지 공격군 분포를 같은 축에 중첩해 그린다. 이 그림 하나가 RQ2 생존 여부를 보여준다.)

여기서 사용하는 구간 경계 0.1 / 0.9는 **유보 밴드가 아니라 보고용 고정 구간**이다.
실제 밴드는 EXP-004에서 예산 역산으로 정한다. 이 값을 `configs/base.yaml`의 `gating`에 옮겨 적지 않는다.

## 5. 성공 / 실패 판정 기준 ← 실행 전에 작성, 이후 수정 금지

판정은 배제 공격군별로 하고, 3~4개 중 **과반**의 결과를 전체 판정으로 삼는다.

- **성공 (신뢰도 단독 게이트 성립):** 배제군 확률질량의 `mass_below_0_1`이 0.3 미만이고,
  `mass_0_1_to_0_9`와 `mass_above_0_9`의 합이 0.7 이상인 경우.
  → 배제군이 정상 확신 구간에 숨지 않는다. 중심축을 **"신뢰도 기반 선택적 검증"**으로 확정.
  EXP-005(OOD 보조 게이트)는 `discarded`로 전환하거나 부록 실험으로 강등한다.

- **실패 (신뢰도 단독 게이트 불성립):** `mass_below_0_1`이 0.5를 초과하는 경우.
  → 배제군이 고신뢰 정상으로 분류된다. RQ2가 신뢰도 단독으로는 성립하지 않는다.
  중심축을 **"신뢰도 + OOD 스코어 기반 선택적 검증"**으로 수정하고,
  EXP-005를 `blocked`에서 `todo`로 전환한다. `ADR-001`에 이 결과를 조건 충족으로 기록한다.

- **판정 보류:** `mass_below_0_1`이 0.3 이상 0.5 이하인 중간 구간.
  → 배제 공격군을 2개 추가해 `EXP-003-r2`로 재실행한다. 그래도 중간이면
  "부분적 성립"으로 보고하고 EXP-005를 병행 실험으로 진행한다.

- **판정 불가 (측정 자체가 무효):**
  - 배제 대상이 `train` 또는 `calib`에 1건이라도 남아 있는 경우. 전체 결과 폐기.
  - 배제군 `n_samples`가 1000 미만인 경우. 해당 공격군만 판정에서 제외하고 나머지로 판단한다.
  - 시드 간 `mass_below_0_1` 표준편차가 0.2를 초과하는 경우. 판정하지 않고 시드를 늘린다.

**이 절의 판정 기준은 결과를 본 뒤 절대 수정하지 않는다.** 이 실험은 중심축을 결정하므로
사후 기준 조정이 곧 사후 합리화가 되며, 심사에서 가장 먼저 지적당하는 지점이다.
