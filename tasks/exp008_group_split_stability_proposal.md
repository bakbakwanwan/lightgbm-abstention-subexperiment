# EXP-008 후속 분할 민감도 분석 제안 (실행 전 검토용)

**상태:** 제안. 이 문서는 실행 가능한 `experiments/EXP-008-*.md` 확정 스펙이 아니다. 판정 구조와 순위 판정 방식은 [D-004 결정 9·10](../docs/CURRENT_DECISIONS.md)을 따른다. 아래 §3의 단일 성공·실패 초안은 채택되지 않았으며, seed별 순위 판정의 종합 규칙·처리량 기준·혼합 결과 해석은 아직 미확정이다. 실행 전에 새 스펙에 고정한다.

## 1. 단일 질문과 주장 범위

**질문:** D-004의 59-feature 완전일치 그룹 분할에서 배정 seed를 바꿨을 때도, EXP-007의 LightGBM confidence가 1차 오류를 낮은 순위로 모으고 EXP-007의 유보 경계가 사전 검증 예산을 지키는가?

이는 동일한 개선 CIC-IDS2017 행 집합을 다시 배정하는 **분할 민감도 분석**이다. 외부 네트워크 데이터에서의 독립 재현, 배포 경계 검증, 2차 검증 후의 탐지 성능으로 주장하지 않는다. 행 단위 랜덤 분할은 이미 EXP-007의 낙관적 참고 분석이므로 반복 대상에서 제외한다. 근거와 허용 범위는 [D-004](../docs/CURRENT_DECISIONS.md) 결정 8이다.

## 2. 입력 조건과 계산 방식

1. 원본 CSV·ZIP, D-001·D-002 관찰군 취급, 59-feature whitelist, Protocol 범주 처리, 이진 판정 임계값, `confidence`, AURC의 동률 처리는 EXP-007과 동일하게 한다. 원본 SHA256과 whitelist SHA256은 D-004 manifest를 기준으로 재검증한다. 확률 보정이나 보정 세트는 만들지 않는다.
2. **분할 seed 후보는 43·44·45로 실행 전에 고정한다.** 각 seed의 그룹 배정은 D-004와 같은 원래 `Label` 계층화, 목표 test 25%, 완전일치 그룹 유지 규칙을 사용한다. 원래 Label 하나라도 train/test 한쪽에서 사라지거나 완전일치 그룹이 교차하면 해당 분할은 무효다. 그룹 제약 때문에 seed별 정확한 행 수는 달라질 수 있으므로 EXP-007 행 수를 강제로 복제하지 않는다.
3. 모델은 EXP-007에서 내부 validation으로 선택한 C06 설정과 `best_iteration=230`을 **고정 입력**으로 사용한다. 각 seed의 외부 train 전체에서 새 모델을 학습한다. 모델 난수 seed는 EXP-007과 같은 값으로 고정하여 분할 배정만 변화시킨다. 새 test 결과를 보고 후보·iteration을 재선택하지 않는다. C06 선택 근거는 [EXP-007 후보 기록](../results/EXP-007/candidate_history.json)과 [실행 manifest](../results/EXP-007/manifest.json)에 있다.
4. seed별 test에서 `aurc`, `random_aurc`, `relative_aurc_improvement`, 전체 오류 count를 산출한다. D-006의 사전 대표 budget을 해당 test confidence로 오프라인 스윕한 결과도 보존해 EXP-007과 **순위 능력**을 비교한다. 같은 confidence의 일부 행을 잘라 budget을 맞추지 않는다.
5. **처리량 이동 검증은 별도로 수행한다.** EXP-007 주 test에서 기록한 1%와 5% `confidence_threshold`를 새 seed의 test에 변경 없이 적용한다. 새 test의 라벨·오류·confidence 분포를 보고 경계를 재선택하지 않는다. 각 고정 경계에서 실제 유보 행 수·비율, budget 초과/미사용분, 오류 포착률, 오류 농축도, 수용 오류율을 기록한다. 관찰군에도 같은 고정 경계를 적용해 포함 수만 보고하며 정답 기반 지표는 만들지 않는다.

EXP-007과 비교할 때는 AURC의 원값뿐 아니라 각 seed의 전체 오류 count와 `random_aurc`를 함께 제시한다. 새 seed의 test는 EXP-007 test와 일부 행을 공유할 수 있으므로 seed별 결과를 서로 독립적인 표본으로 취급하거나 신뢰구간·유의성을 주장하지 않는다.

## 3. 미채택 단일 판정 초안 — 새 별도 판정 기준이 필요함

**기술적 유효성:** 모든 원본·피처 SHA256, 모집단 및 관찰군 취급, 59-feature 그룹 교차 0개, 원래 Label 생존, 유한한 예측 확률·confidence, AURC 순서 불변성 검증을 통과해야 한다. 원본 행 수는 유지하되 train/test의 seed별 정확한 행 수는 검증 결과로 기록한다. 하나라도 실패하면 기술적 판정 불가이며 다른 seed의 좋은 결과로 대체하지 않는다.

**성공:** 세 seed 모두 전체 오류가 1건 이상이고 아래를 모두 만족한다.

- 각 seed에서 test confidence를 사용한 오프라인 budget 스윕이 D-006 §2 항목 33의 성공 기준을 만족한다.
- 각 seed에서 EXP-007 **고정 1% 경계**의 실제 유보 행 수가 0보다 크고 해당 seed test 행 수의 1% 상한을 넘지 않으며, D-006 §2 항목 32의 개선 지점 조건을 만족한다.
- 각 seed에서 EXP-007 **고정 5% 경계**의 실제 유보 행 수가 0보다 크고 해당 seed test 행 수의 5% 상한을 넘지 않으며, D-006 §2 항목 33의 5% 오류 농축·수용 위험 조건을 만족한다. 이 조건의 실제 유보율 하한은 **고정 경계의 실제 유보율**에 적용한다.

고정 경계의 유보 행 수 상한은 부동소수점 근사 비교가 아니라 `n_abstained <= floor(target_abstention_rate × n_test)`로 검사한다. 상한 미사용분은 성공 여부와 함께 보고하며, 유보율이 목표보다 작다는 이유만으로 임의로 경계를 올리지 않는다.

**실패:** 기술적으로 유효하고 세 seed 모두 오류가 존재하지만, 어느 한 seed에서 고정 1% 또는 5% 경계가 해당 처리량 상한을 초과하거나, 세 seed 중 둘 이상에서 D-006 §2 항목 34의 오프라인 순위 실패 조건에 해당할 때다. 또한 둘 이상에서 고정 5% 경계의 유보가 0이거나 오류 농축도·수용 위험이 D-006 §2 항목 34의 실패 쪽에 해당하면 실패다. 결론은 “같은 데이터의 그룹 분할 seed 변화에서 현재 순위 또는 고정 경계 처리량이 유지되지 않았다”로 제한한다.

**과학적 판정 불가:** 기술적으로 유효하지만 한 seed라도 전체 오류가 0건이거나 성공·실패 어디에도 들지 않는 약한/혼합 신호일 때다. 이 경우 성공한 seed만 선택해 EXP-008 성공으로 바꾸지 않는다.

## 4. 실행 전 준비와 EXP-007과의 차이

- `experiments/EXP-008-*.md` §4에 위 기준을 확정하고, 독립 라벨 데이터 검증은 그 스펙에 섞지 않는다. 새 데이터가 확보되면 별도 실험으로 다룬다.
- 분할 생성기와 실행 코드의 D-004 seed 42·EXP-007 전용 식별자·외부 train/test 행 수 강제값을 **config 기반**으로 일반화한다. 기존 구현 파일의 복사본을 만들지 않는다. 새 seed별 split과 결과를 별도 디렉토리에 기록하고 기존 `results/d004_splits/` 및 `results/EXP-007/`은 덮어쓰지 않는다.
- 확정 스펙과 코드 커밋 후 clean worktree, 결과 디렉토리 미존재, 테스트 통과를 guard로 확인한다. 결과의 `metrics.json`에는 실행 commit, seed별 설정, 데이터 버전을 기록하고 해석은 넣지 않는다.
- EXP-007의 `group_seed42`를 기준 열로, 새 세 seed를 비교 열로 둔다. seed별 전체 오류 수, AURC 대비 무작위 기준, 오프라인 budget 효과, **고정 경계의 실제 유보율**을 각각 비교한다. EXP-007의 `row_random_seed42`는 낙관적 참고 열로만 유지한다.

## 5. 별도 데이터 확보 과제

같은 원본 행을 다시 나누는 EXP-008만으로는 독립 환경 일반화를 검증할 수 없다. 먼저 원 제공처의 다른 라벨 데이터에서 **입력 피처 정의·단위·결측, 정상/공격과 Attempted/무효 클래스 처리, 원본 SHA256, 평가 행 선택 규칙**을 감사해야 한다. 이 감사가 통과되기 전에는 EXP-007의 59-feature 모델에 단순 이름 변경만 적용해 독립 test 성능을 주장하지 않는다.
