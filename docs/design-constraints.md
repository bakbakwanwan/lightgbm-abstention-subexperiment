# 설계 제약과 기각 이력

이 문서는 지시문이다. 아래 항목은 설계 검토에서 근거를 갖고 결정된 것이며,
코드 작성 중 "더 나은 방법"으로 보이는 대안이 떠오르더라도 여기서 기각된 것이면 따르지 않는다.
제약을 바꿔야 한다고 판단되면 코드를 고치기 전에 사용자에게 먼저 보고한다.

---

## A. 준수 사항

1. **보정을 거친 확률만 임계값 판단에 쓴다.** LightGBM의 원시 출력은 보정되지 않은 점수이며,
   여기에 절대 임계값을 적용하면 유보 구간이 아무 의미도 갖지 못한다.
2. **보정기는 학습 데이터와 분리된 데이터로 적합시킨다.** 학습에 쓴 데이터로 보정하면
   과신 정도가 과소평가되어 ECE가 실제보다 좋게 나온다.
3. **유보 구간 폭은 config에서만 주입한다.** `configs/base.yaml`의 `gating.lower/upper`가
   `null`인 것은 미완성이 아니라 의도된 상태다. 예비 실험 전에 채우지 않는다.
4. **임계값 축소는 비대칭으로 설계한다.** 상·하한을 대칭으로 좁히면 고신뢰 공격 측이
   검증 없이 확정되어 오탐이 오히려 늘어난다. 목표에 역행한다.
5. **배제 공격군은 학습·보정 양쪽에서 모두 제외한다.** 보정 단계 누수가 가장 놓치기 쉽다.
6. **LLM은 2차 검증기로 구현한다.** 유보된 플로우에 대해서만 호출되며, 전량 처리 경로에
   LLM이 들어가는 설계는 만들지 않는다.
7. **XAI 출력은 LLM 프롬프트의 입력으로만 쓴다.** 가설 검증형 추론을 유도하는 재료이지
   판정 근거가 아니다.
8. **환류 대상은 신뢰도 보정과 임계값 조정까지다.**

## B. 금지 사항 (기각된 대안)

9. **라벨 재생성·재라벨링 금지.** 검증 결과를 학습 라벨로 되먹이는 구조는 라벨 오염과
   평가 오염을 동시에 일으킨다. 기각됨.
10. **XAI 양방향 피드백 루프를 중심 기여로 구현하지 말 것.** 임계값 진동을 유발하며,
    가장 실패 확률이 높은 요소를 프로젝트 생존 조건으로 만들게 된다. 기각됨.
11. **3분기 판정(정상/의심/공격) 용어와 구조를 재도입하지 말 것.** abstention 프레이밍으로
    대체 확정됐다. 코드 식별자도 `abstention`을 쓴다.
12. **처리 지연에 대한 구체 수치를 코드 주석이나 문서에 쓰지 말 것.** 측정 전 수치 주장은
    검증 불가능한 리스크다.
13. **정확도(accuracy)를 주 지표로 쓰지 말 것.** 클래스 불균형이 심해 무의미하다.

## C. 조건부 항목 (EXP-003 결과에 종속)

14. 게이트를 신뢰도 단독으로 구성할지, OOD/이상 스코어 보조 게이트를 병행할지는
    **아직 결정되지 않았다.** 배제 공격군이 고신뢰 "정상"으로 분류되면 Agent가 검증 기회를
    얻지 못하므로 보조 게이트가 필수가 된다.
15. 따라서 `gating` 모듈은 스코어 소스를 교체 가능한 구조로 작성한다. 신뢰도 단독을
    하드코딩하지 말 것.

## D. 용어

16. 코드 식별자와 출력 필드명은 `docs/glossary.md`를 따른다. 폐기된 표현
    ("피처 기여도", "판단 근거 특징", "재라벨링", "3분기")을 쓰지 않는다.
