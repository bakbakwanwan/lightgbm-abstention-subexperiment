## 0. 데이터셋 명칭 규약

CNS2022 연구진이 재처리·재라벨링한 CIC-IDS2017을 **`CICIDS2017_CNS2022_reprocessed`** 로 표기하고,
본문에서는 **재처리판**으로 줄여 쓴다. 원본 공개판(UNB 배포)은 **공개판**으로 표기해 구분한다.

- 이는 **본 연구의 내부 명칭**이며 공식 배포 명칭이 아니다(배포처 표기는 "improved" 계열).
  논문 첫 등장 시 정의 문장과 배포 명칭을 병기한다.
- 로컬 경로는 `data/CICIDS2017_improved/`로 **미정정 상태**다. 경로 변경은 별도 커밋으로 분리한다.

---

## 1. 이 하위실험의 질문

**"1차 게이트(LightGBM)에 유보 구간이 실제로 존재하는가."**

성능 측정이 아니다. 존재 주장이다. 이 구분이 이하 모든 결정의 근거다.

- 판정 지표는 **AURC**(risk-coverage 곡선 아래 면적).
- AURC는 단조변환 불변이므로 **확률 보정 전에도 계산된다.**
- 따라서 이 실험은 **보정(calibration)을 수행하지 않는다.** ECE/Brier는 범위 밖.

## 2. 확정된 결정

### D-001 — Attempted 계열: 유보 (관찰군)

`Label`이 `- Attempted`로 끝나는 행 **11,979행**(전체의 0.570%)은
학습·보정·성능 지표 산출에서 **제외**한다. 별도 관찰군으로 보존한다.

근거: 재처리판은 오염 플로우를 삭제하지 않고 재라벨링해 남겨두었을 뿐이며,
공격으로 볼지 정상으로 볼지의 판단은 사용자 몫으로 남아 있다.

`Attempted Category` 코드북(0~6)은 확정·검증되었다 — `dataset_audit_2026-09-11.md` §3-2.
이 컬럼은 라벨 파생 컬럼이므로 **피처로 사용하지 않는다.**

### D-002 — DoS Hulk: 무효 클래스 관찰군

`Label == "DoS Hulk"` **158,468행**은 독립된 무효 클래스 관찰군으로 분리한다.
학습·보정·성능 지표에서 **제외**한다. D-001 관찰군과 **합산하지 않는다.**

근거: Improved CIC-IDS 2017 Documentation이 이 공격을 "mis-implemented"로 명시.
재처리판은 이를 문서에 기록했을 뿐 데이터에서 해소하지 않았다.

### D-003 — 피처 구성: 59개 포함 / 32개 제외 (종결)

전체 91열 중 **59열만** 모델 입력으로 사용한다. 전체 목록은 `configs/features_whitelist.json`.

주요 제외 항목과 사유:

| 컬럼 | 사유 |
|---|---|
| `Flow ID`, `Src IP`, `Dst IP`, `Timestamp`, `id` | 식별자 누수. Timestamp는 라벨링 로직 그 자체 |
| `Src Port` | CNS2022가 누수 피처로 지목 |
| `Dst Port` | **제외 확정, 재도입 없음.** 포트별 공격률 편중(80번 62%, 8080번 97%)이 유효 신호가 아니라 테스트베드 아티팩트를 암기시킨다 |
| `Protocol` | 정수 매핑이 서열로 오독됨. 제외 확정 |
| `Attempted Category` | 라벨 파생 컬럼 |
| 나머지 | 상수·항등식 중복 등, 축 A~H 심사 결과 |

**파생 피처·window·집계 피처는 만들지 않는다.** 59개 전부 원본 flow-level 컬럼이며,
행끼리 정보가 오가지 않는다. 따라서 window leakage 문제는 이 설계에 존재하지 않는다.

### D-004 — 분할 프로토콜 (잠정, 정식 기록 전)

```
대상 1,929,529행
  ├─ train 75% (약 1,447,147)
  └─ test  25% (약   482,382)   ← 한 번만 평가
```

- **단순 계층 랜덤 2분할.** 그룹 분할·시간 분할·LOAO 없음.
- **계층화 기준 = 원래 공격 종류(`Label`)**, 이진 라벨이 아니다.
  희소 클래스가 test에 아예 들어가지 않는 것을 막기 위함.
- calibration set 없음, 교차검증 없음 (§1 참조).
- test 예측 확률을 **전량 파일로 저장**해 오프라인으로 유보 밴드를 스윕한다.
  임계값을 사전에 고정하지 않는다.
- seed는 우선 **42** 하나. 반복 여부는 1회 결과를 보고 판단.

**해석 규칙(실행 전 고정):** 랜덤 분할은 leakage로 인해 모델에 가장 유리한 조건이다.
따라서 유보 구간이 **발견되면** 결론은 보수적이고 강하다.
**발견되지 않으면** "존재하지 않는다"가 아니라 **"이 분할 조건에서는 관찰되지 않았다"**까지만
결론 내리고, 더 엄격한 분할로 재검증한다.

### D-005 — 희소 클래스 (잠정)

Heartbleed 11, Web SQLi 13, Web XSS 18, Infiltration 36, Web BF 73행.

- 오버샘플링·복제·삭제 **하지 않는다.**
- seed 반복으로 변동폭을 재지 **않는다** (표본이 작아 결과가 자명함).
- **보고 규칙:** 클래스별 지표에는 test 표본 수를 반드시 병기한다
  (예: `Heartbleed recall 0.667 (n=3)`). 소표본 클래스에 대해 성능 주장을 하지 않는다.

## 4. 다음 작업 (착수 전 필수)

**59-feature 기준 중복 행 및 class overlap 측정.**
지시서: `tasks/task_duplicate_class_overlap_measurement.md`

이유: 59개 값이 동일한데 라벨이 갈리는 행은 어떤 모델도 구분할 수 없고,
그 자체로 유보 구간처럼 보이는 영역을 만든다. 규모를 모르면 실험 결과를 해석할 수 없다.

**주의:** 과거에 같은 항목을 `5-tuple + Timestamp` 일치 기준으로 판정해 0건이 나온 기록이 있으나,
`Timestamp` 고유값이 2,077,011개라 그 조건은 사실상 통과 불가능했다. **그 0건은 무효다.**

또한 현재 PC에는 `dataset_manifest.json`이 없고, 과거 기록에도 SHA256 **값**이 남아 있지 않다
("일치"라는 판정만 있음). 측정 전에 manifest를 재생성하고 **해시 값을 문서 본문에 기록**한다.

## 6. 이 문서의 유지 규칙

1. 새 결정이 확정되면 **여기에 먼저** 반영한다.
2. 폐기된 문서를 "정리"해서 현행처럼 보이게 만들지 않는다. 격리하거나 폐기 표시를 유지한다.
3. 정책을 "해소"로 표시하기 전에 **코드에 반영되었는지 확인**한다
   (과거 정책 1-12가 문서상 "해소"였으나 코드에 미구현이었던 사례).
