## 서브실험의 목적 (전제)

- **용도:** ① 본 연구 착수 전 내부 검증 ② 별도 논문·포스터 제출
- **답할 질문:** 판정을 **유보(abstention)해야 할 구간을 식별할 수 있는가**, 그리고 그 구간의 비율을 조절할 수 있는가
- **지원서 초록의 RQ1에 대응** — "유보 구간 비율에 따라 오탐률과 처리 지연이 어떤 트레이드오프를 형성하며,
  소수 비율의 심층 검증만으로 유의미한 오탐 저감이 가능한가"
- **범위 밖:** 탐지 성능 경쟁, 타 모델 비교, 2·3차 계층(LLM·RAG) 구현

**이 하위실험의 질문은 하나다: "유보 구간이 실제로 존재하는가."**
성능 측정이 아니라 존재 주장이다. 이 구분이 이하 모든 결정의 근거다.

- 판정 지표는 **AURC**(risk-coverage 곡선 아래 면적).
- AURC는 확정된 confidence의 순위와 동률을 보존하는 엄격한 단조변환에 불변이다.
- 이 실험은 confidence 순위 평가에 한정하므로 **보정(calibration)을 수행하지 않는다.
  ECE/Brier는 범위 밖이다.**
  이 결정은 `_superseded/` 아래의 `design-constraints.md`·`metrics-spec.md`·`glossary.md` 구판과
  정면으로 충돌한다. 그 문서들은 폐기되었다.

## D-001. Attempted 라벨의 이진 라벨 매핑

**확정일:** 2026-09-11

### 1. 질문

재처리판의 `X - Attempted` 계열 11종(11,979행, 전체의 0.570%)을
이진 게이트 학습에서 공격(1)으로 볼 것인가, 정상(0)으로 볼 것인가, 아니면 다르게 처리할 것인가.

### 2. 결정

**전부 "유보"로 취급한다.** 운영상 다음을 의미한다.

- **학습·보정 세트에서 제외한다.** 이진 분류기는 '유보'를 클래스로 학습할 수 없으므로
  (유보는 확률 임계값에서 파생되는 것이지 라벨이 아님), 학습에 넣으면 0/1 중 하나로
  강제해야 하고 이는 결정과 모순된다.
- **평가에서는 별도 관찰군(경계 사례 집합)으로 둔다.** 검증 질문은
  "이 샘플들이 실제로 유보 밴드에 떨어지는가"이다.
- **관찰 시 `Attempted Category` 사유 코드별로 분리해서 본다.** 통합 분포와 코드별 분포를 모두 산출한다.
- 이진 라벨: `BENIGN → 0`, 명확한 공격 → `1`, Attempted 11종 → 라벨 없음(관찰군).
  (**D-002 반영:** `DoS Hulk`가 무효 클래스 관찰군으로 분리되어 공격 라벨은 **14종**이다.)

### 3. 근거

**(a) 사용자 판단 (1차 근거)**

Attempted에 해당하는 모든 사유가 악성 행동으로 보일 여지가 있다.
공격(1)으로 단정하면 그 위험을 모델에 학습시키게 되므로, 판단을 2차 LLM 계층으로 넘기는 것이
프레임워크 설계 의도에 부합한다. 유보 판정 구간의 표본도 이로써 확보된다.

**(b) 원자료의 성격이 이를 뒷받침함**

CNS2022 논문 §IV-A-2는 Attempted 재배정 사유 중 startup/teardown artifact에 대해
**"악성 페이로드가 없어 단일 플로우 맥락에서는 정상 사용자의 웹 브라우징과 의미적으로 동일"**하다고 기술한다.
즉 원저자들이 직접 "단일 플로우로는 판별 불가"라고 판정한 집합이다.
→ 출처: `Error_Prevalence_in_NIDS_datasets...pdf` §IV-A-2

**(c) 순환 논증 회피**

Attempted 판정은 CNS2022 저자 2인이 5개월간 원본 .pcap을 수작업 분석해 내린 **외부 기준**이다
(출처: 같은 논문 §III Methodology). 우리가 설정한 임계값으로 우리 임계값을 평가하는 순환을 피할 수 있다.

**(d) 비용이 낮음**

전체의 0.570%에 불과해 학습에서 제외해도 손실이 작다.

`Attempted Category` 코드북(0~6)은 확정·검증되었다 — `docs/dataset_audit_2026-09-11.md` §3-2.
이 컬럼은 라벨 파생 컬럼이므로 **피처로 사용하지 않는다**(D-003 축 A). 단 데이터에서는 보존한다.

### 4. 결과적으로 따라오는 영향

아래 표는 **결함이 확인된 구 분할(2단계 파이프라인) 기준**이므로 D-004 적용 후 재산출이 필요하다.
이 표의 용도는 "Attempted 제외 시 어떤 공격군이 위태로워지는지"를 분할 설계의 입력으로 삼는 것이다.

| 항목 | Attempted 포함 | 제외 후 |
|---|---|---|
| train 공격 총계 | 192,656 | 189,175 |
| train 내 Portscan 계열 비중 | 95.7% | **97.5%** |
| train 내 Web Attack - Brute Force | 781행 (전부 Attempted) | **0행 — 학습에서 소멸** |
| train 내 Botnet | 3,196행 | **496행** (4,067/4,803 = 84.7%가 Attempted) |

- **Web Attack - Brute Force는 train에서 완전히 사라진다.** 명확한 Brute Force는 원래 train에 0건이고,
  train에 있던 781행이 전부 Attempted였기 때문.
- **Botnet은 496행으로 축소된다.**
- Portscan 편중이 더 심해진다.

### 5. 미결

- ~~코드 5 미확정 / 코드 2·3·4 추정~~ → **전부 해결(2026-09-11).**
  코드북의 1차 출처는 **Improved CIC-IDS 2017 Documentation의 공격별 Labelling logic**이며
  (논문이 아님, 통합 정의표는 존재하지 않음), 문서에 명시된 판정 조건을 **우리 데이터로 검증 완료**했다.
  코드 4의 `Src Port ∈ {48678, 43664}`와 코드 6의 `Fwd len==0 & Duration≥199800`이 각각
  정확히 일치하여 코드북은 확정 상태다. 상세: `docs/dataset_audit_2026-09-11.md` §3-2.
  코드 5 = **Attack Implemented Incorrectly** (DoS Slowloris 138행).
- ~~**DoS Hulk 158,468행의 취급**~~ → **해결(2026-09-11): D-002로 별도 결정.**
- **민감도 확인 권장:** Attempted를 공격(1)으로 매핑한 버전을 1회 추가 학습해 비교.
  "매핑 선택이 신뢰도 분포를 얼마나 바꾸는가" 자체가 결과로서 가치가 있음.

### 6. 관찰 시 기대 패턴 (가설, 실행 전 기록)

사유 코드 0과 1은 성격이 정반대이므로 확률 분포가 갈릴 것으로 예상한다.

- **코드 0 (Empty Payload, 4,845행):** 내용이 없어 정상과 구분 불가 → **중간 구간**에 분포 예상
- **코드 1 (Port/System closed, 4,067행):** 공격 의도는 명백했으나 대상이 죽어 도달 실패
  → **공격 쪽 고확률 구간**에 분포 예상
- **코드 5 (Attack Implemented Incorrectly, 138행):** 공격 의도는 있었으나 구현·실행이 어긋난 경우
  → 코드 1과 유사하게 **공격 쪽**에 기울 것으로 예상하나, 표본이 작아 판단 근거로 쓰지 않는다

두 집단이 실제로 다른 구간에 떨어진다면, 모델이 이 차이를 포착하고 있다는 증거가 된다.
같은 구간에 뭉친다면 그 자체로 "신뢰도만으로는 두 상황을 구분하지 못한다"는 결과다.

**이 가설은 실행 전에 기록되었으며, 결과를 본 뒤 수정하지 않는다.**

## D-002. DoS Hulk(158,468행)의 취급 — 무효 클래스 분리

**확정일:** 2026-09-11
**선행:** D-001 (Attempted 매핑). **후행:** D-003 (피처 확정) → D-004 (분할 재설계).

### 1. 질문

Improved CIC-IDS 2017 Documentation이 **"의도한 대로 쓸 수 없다"**고 명시한 `DoS Hulk` 158,468행을
학습·평가에서 어떻게 취급할 것인가. 완전 배제인가, Attempted로 편입인가, 공격으로 유지인가.

### 2. 결정

**독립된 제3의 관찰군으로 분리한다.** (`invalid_class_observation`)

- **학습·보정 세트에서 제외한다.** 이진 라벨(0/1)을 부여하지 않는다.
- **평가에서는 관찰군으로 유지하되, D-001의 Attempted 관찰군과 절대 합산하지 않는다.**
  두 관찰군은 끝까지 분리해서 보고한다.
- 주 지표(risk-coverage, AURC, FPR/FNR)는 **DoS Hulk를 제외한 집합에서 산출**하며,
  보고 시 "DoS Hulk 제외 기준"임을 반드시 명시한다.
- 행을 삭제하지 않는다. 태그로 분리만 한다(되돌릴 수 있는 형태).

**관찰군은 이제 둘이다.**

| 관찰군 | 대상 | 행 수 | 성격 |
|---|---|---|---|
| Attempted 관찰군 (D-001) | `X - Attempted` 11종 | 11,979 | **플로우 단위** 애매함 |
| 무효 클래스 관찰군 (D-002) | `DoS Hulk` | 158,468 | **클래스 단위** 무효 |

### 3. 근거

**(a) 1차 출처 — Improved CIC-IDS 2017 Documentation, DoS Hulk 절**

- 사용된 공격 도구가 deprecated 버전이며, HTTP `Connection` 헤더를 `Keep-Alive`가 아닌 `close`로 설정한다.
- 그 결과 서버가 즉시 FIN을 보내 연결을 닫으므로, **공격이 무력화된 상태로 시뮬레이션되었다.**
- 문서 표현: `This attack is mis-implemented.`
- 문서는 **원칙적으로 전체를 `Attempted (Category 5 - Attack Implemented Incorrectly)`로 분류해야 한다**고 서술한다.
- 저자들은 이 클래스를 의도대로 쓸 수 없다고 명시했으며, **해결책은 테스트베드에서의 재실행뿐**이다.
  우리는 재실행할 수 없다.

**(b) 연구진의 라벨 유지는 유효성 보증이 아니다**

연구진은 위와 같이 기록하면서도 트래픽이 여전히 비정상적으로 보인다는 이유로
대량의 flow를 일반 `DoS Hulk`로 유지했다. 이는 **실용적 타협**이며,
문서 본문이 무효를 명시한 이상 **그 라벨을 그대로 쓰면 그들이 하지 않은 보증을 우리가 하는 셈**이 된다.

**(c) 유지할 경우 측정 대상이 편향되는 방향이 예측된다 — 배제의 결정적 사유**

무력화된 Hulk는 `Connection: close` → 서버 즉시 FIN → **짧고 대량인 연결** 패턴이 되어
정상 트래픽과 매우 잘 구분된다. 즉 **인위적으로 탐지하기 쉬운 공격**이다.
이것이 명확한 공격 전체의 **31.4%**를 차지하면 예측 확률이 극단으로 쏠리고,
**유보 밴드를 인위적으로 비게 만든다.**
하필 이 서브실험이 측정하려는 값(유보 구간의 존재 여부)을 직접 편향시키므로 허용할 수 없다.

**(d) Attempted 관찰군과 합치지 않는 이유**

D-001의 Attempted 11종은 **"이 플로우가 애매하다"**는 플로우 단위 판정이다.
DoS Hulk는 **"이 클래스 전체가 무효다"**로 층위가 다르다.
합치면 "유보 밴드가 애매한 플로우를 잡는가"라는 질문이
"유보 밴드가 망가진 클래스를 잡는가"로 오염된다.
또한 합칠 경우 관찰군 170,447행 중 **93%가 Hulk**가 되어 통합 지표를 지배한다.

**(e) 완전 배제(행 삭제)를 택하지 않은 이유**

삭제하면 이 15만 행이 우리 모델에서 어떻게 거동하는지 **영영 알 수 없다.**
관찰군으로 두면 정보를 보존하면서도 (c)의 편향을 피할 수 있다.
비용은 "관찰군이 하나 늘어나 서술이 한 단계 복잡해진다"는 것뿐이다.

### 4. 결과적으로 따라오는 영향

- 학습 대상에서 빠지는 총량: **170,447행 (전체의 8.12%)** — 행 수 상세는 §대상 행 집합 참조
- 공격 클래스 최대 규모가 `DoS Hulk`(158,468) → `Portscan`(159,066)으로 바뀐다.
  (Portscan이 근소하게 더 크므로 순위 자체는 유지)
- 구 분할에서는 학습에 아무 변화가 없었다 — Hulk가 이미 train에 0건이었기 때문.
  이 결정의 학습 측 효과는 **D-004 적용 이후에 발생한다.**

**D-004에 전달한 제약**

- `DoS Hulk`는 **train에 배정되지 않아야 한다.** 관찰군으로 고정.
- 마찬가지로 Attempted 11종도 train 배정에서 제외(D-001).
- 따라서 분할 대상은 1,929,529행이다.

### 5. 미결

- 태그 컬럼의 정확한 명칭과 스키마 — 구현 시 확정 (`observation_group` 단일 컬럼에
  `none` / `attempted` / `invalid_class` 값을 두는 방식 권장. 컬럼 두 개보다 단순)
- `DoS Hulk - Attempted` 581행의 취급 — 현재 D-001에 의해 Attempted 관찰군.
  D-002와 겹치는 영역이나, **라벨상 Attempted가 명시된 행이므로 D-001을 우선 적용**한다.
  즉 581행은 Attempted 관찰군, 158,468행은 무효 클래스 관찰군.
- 민감도 확인 권장: DoS Hulk를 공격(1)으로 포함한 버전을 1회 추가 산출해
  "무효 클래스 포함 여부가 유보 밴드 비율을 얼마나 바꾸는가"를 수치로 제시.
  (c)의 예측이 맞는지 검증하는 실험이며, 맞다면 그 자체가 결과가 된다.

### 6. 관찰 시 기대 패턴 (가설, 실행 전 기록)

**무효 클래스 관찰군(DoS Hulk)은 공격 쪽 고확률 구간에 몰릴 것으로 예상한다.**
근거는 (c) — 무력화된 Hulk가 오히려 정상과 더 잘 구분되는 패턴을 갖기 때문이다.

- **예상대로 고확률에 몰리는 경우:** "신뢰도 게이트는 데이터 결함에서 비롯된 가짜 확신을 걸러내지 못한다"는 결과가 된다.
  이는 2·3차 계층(외부 지식 기반 검증)의 필요성으로 직접 연결되며, **부정적 결과가 아니라 활용 가능한 결과다.**
- **중간 구간에 분포하는 경우:** 모델이 이 클래스의 이상함을 포착하고 있다는 뜻이며,
  신뢰도 게이트의 유효 범위가 예상보다 넓다는 근거가 된다.

**이 가설은 실행 전에 기록되었으며, 결과를 본 뒤 수정하지 않는다.**

## D-003. 피처 구성 확정 — **종결 (2026-09-12)**

**착수일:** 2026-09-12
**입력 자료:** `docs/feature_inventory_2026-09-12.md` (원본 CSV 91개 컬럼 전수 조사)

> **목록의 정본은 `configs/features_whitelist.json`이다.**
> 이 문서는 목록을 옮겨 적지 않는다. 컬럼 하나의 포함·제외 여부가 궁금하면 그 파일을 연다.
> 아래는 **결정의 방법론과 근거**만 기록한다.

### 0. 대전제 — 원본 데이터셋 한정

**whitelist는 원본 91개 컬럼 위에서만 정의한다.** 이 91개가 결정의 전체 모집단이며,
여기에 없는 이름(파이프라인이 생성하는 컬럼 등)은 논의 대상이 아니다.
파이프라인이 무엇을 추가하든 whitelist에 없으므로 자동 배제되며, 열거할 필요도 없다.

이 대전제는 **작업 중 두 차례 위반되었다**(`docs/dataset_audit_2026-09-11.md` §8 오류 5 참조).
현재 작업의 최대 리스크로 식별되어 명시적 가드로 승격되었다.

### 1. 확정된 방법론

**(가) 정의 방식 — blacklist에서 whitelist로 전환 (확정)**

- 학습에 쓸 컬럼을 명시적으로 열거한다.
- **목록에 없는 컬럼은 학습 입력에 들어갈 수 없다.**
- 91개 전 컬럼에 대해 "포함" 또는 "제외 + 사유 코드"를 **빠짐없이** 부여한다. 미분류 0개.
- **근거:** 기존 blacklist 사고 때문에 `Src Port`가 어떤 정책에도 오르지 않은 채 통과했고,
  정책 1-12는 목록에 있었으나 구현되지 않았다(오류 4). whitelist는 빠뜨림을 구조적으로 불가능하게 한다.

**(나) 판단 축 8개 (확정)**

각 컬럼을 순차 통과시키며, 앞 축에서 걸리면 뒤는 묻지 않는다.

| 축 | 질문 | 상태 |
|---|---|---|
| A | 라벨링 절차에서 파생되었는가 | **종결** |
| B | 테스트베드의 물리적 배치를 드러내는가 (환경 누수) | **종결** |
| C | 부기(bookkeeping) 컬럼인가 | **종결** |
| D | 계산 오류를 담고 있는가 | **종결** |
| E | 정보를 갖는가 (분산) | **종결** |
| F | sentinel 값이 수치로 오독되는가 | **종결** |
| G | 실시간성 가정과 충돌하는가 | **종결** (범위 선언) |
| **H** | **근사 중복 (컬럼 쌍·집합의 관계)** | **종결** — 단, 상관 기반 판정은 이연(§5-5-6) |

축 H는 원안에 없었고 2026-09-12에 추가되었다(사용자 승인).
축 A~G가 컬럼을 개별 판정하는 데 반해 축 H는 **컬럼 간 관계**를 본다.

축 B의 판단 기준: **"실제 운영 환경에서 이 값이 공격과 정상을 가르는 정보로 일반화되는가?"**

**(다) 축 E는 라벨을 보지 않고 판단한다 (확정)**

컬럼의 의미와 구조적 통계(고유값 수, 0 비율, 계산 정의)만으로 정한다.
**근거:** 전체 데이터의 라벨을 보고 피처를 고르면 설계 단계 누수가 되고,
"피처 선택은 분할과 독립"이라는 원칙(§2)이 약해진다.
예: `Subflow Bwd Packets`가 `{0,1}`뿐인 것은 "서브플로 패킷 수"라는 정의와 모순되므로
라벨 없이도 계산 결함으로 판정 가능하다.

### 1-1. 사유 코드 체계 (확정, 2026-09-12)

사유는 서술이 아니라 **아래 고정 어휘**로 기록하며, 목록에 없는 사유가 필요하면 코드를 먼저 추가한다.

| 코드 | 의미 | 판정 성격 |
|---|---|---|
| `LABEL` | 라벨 또는 라벨에서 파생된 컬럼 | 정의상 자명 |
| `LEAK_ENV` | 테스트베드의 물리적 배치를 드러냄 (IP·포트·5-tuple) | 의미 판단 |
| `LEAK_TIME` | 시각 또는 그 대리 변수 | 의미 판단 |
| `DEFECT_CALC` | 계산 오류를 담고 있음 | **측정으로 확인** |
| `REDUNDANT_EXACT` | 다른 컬럼의 결정론적 함수 (예외 0건) | **측정으로 확인** |
| `REDUNDANT_NEAR` | 높은 상관의 근사 중복 | **측정으로 확인** |
| `NO_IMPACT` | 비영 행 수가 집계 지표를 움직일 수 없는 수준 | **측정으로 확인** |
| `INCLUDE` | 학습 입력에 포함 | — |

**`NO_IMPACT`에 관한 주의.** 이 코드는 **"정보가 없다"가 아니라 "영향을 줄 수 없다"**를 뜻한다.
컬럼이 N개 행에서만 비영이면 바꿀 수 있는 예측은 최대 N개 행인데,
이 서브실험의 측정 대상(risk-coverage 곡선, 유보 밴드 비율)은 집계량이라 극소수 행으로 움직이지 않는다.
**라벨을 보지 않고 "결과에 영향 불가"를 판정할 수 있는 유일한 경로**이므로 확정 (다)와 일관된다.

**포함 컬럼의 처리 지시는 사유 코드가 아니라 별도 필드**(`encoding`, `dtype` 등)로 기록한다.

### 2. 피처 선택은 분할 프로토콜과 독립이다 (확정)

**의존성 방향 점검 결과, 모든 실질적 의존은 피처 → 분할 한 방향이다.**

- 정책 1-6(상수/중복의 train 기준 판단)이 분할에 의존하나, 이는 오히려 순서를 뒷받침한다 —
  흔들리는 컬럼을 whitelist에 미리 명시하면 의존 자체가 끊긴다.
- 근사 중복 측정, 피처 기반 분할 모두 피처가 선행되어야 한다.
- **반대 방향(피처 선택이 분할에 의존)은 성립하지 않는다.** 축 A~G가 전부
  의미·누수·계산 결함 기준이며 예측력 기반 선택이 아니기 때문이다.

**따라서 지금 내리는 어떤 결정도 나중의 분할 선택지를 좁히지 않는다.**
whitelist는 명세일 뿐 데이터를 삭제하지 않으며, 원본 CSV에는 91개 컬럼이 항상 존재한다.

**이에 따라 삭제된 문구:** 초안에서 `Src IP`·`Dst IP`·`Timestamp`에 붙였던
"단, 분할 계산에 필요하므로 중간 단계까지 보존" 절을 삭제한다.
이는 **단일 테이블을 순차 변형하는 폐기된 파이프라인 구조를 전제한 표현**이었다.
어떤 파이프라인이든 필요하면 원본에서 다시 읽으면 되므로 "보존" 대상은 존재하지 않는다.

### 3. 축 A — 라벨링 절차 파생 (종결)

`Label`(y 생성의 원천)과 `Attempted Category`(라벨 파생) 둘을 제외한다.

`Attempted Category`는 `BENIGN`과 명확한 공격이 모두 `-1`이므로 이진 라벨을 직접 누설하지는 않는다.
그러나 D-001에 의해 Attempted 행이 학습에서 빠지므로 **학습셋 안에서는 전량 `-1`인 상수**가 되어
정보가 없고, 남기면 관찰군 소속만 드러낸다.
단 **D-001이 요구하는 사유 코드별 관찰군 분포 산출**과 D-002의 관찰군 태그 생성에 필요하므로
**데이터에서는 삭제하지 않고 whitelist에서만 제외**한다.

### 4. 축 B — 환경 누수 (종결)

#### 4-1. `Dst Port` 제외 — 근거와 부작용

**사용자 판단:** 해당 포트에 대한 공격은 실제로도 유효한 경우가 많으나,
이 데이터셋에서는 그 점을 고려하는 것보다 **오류를 답습하는 형태가 될 가능성이 높다.**

**측정으로 뒷받침됨 (원본 전량, 2,099,976행)**

| Dst Port | 행 수 | 전체 비중 | 공격 비율 |
|---|---|---|---|
| 53 (DNS) | 957,982 | 45.62% | **0.02%** |
| 80 (HTTP) | 441,133 | 21.01% | **62.38%** |
| 443 (HTTPS) | 390,267 | 18.58% | **0.08%** |
| 8080 | 5,173 | 0.25% | **97.18%** |
| 21 (FTP) | 6,833 | 0.33% | **63.65%** |
| 22 (SSH) | 8,548 | 0.41% | **38.98%** |
| 123 (NTP) | 23,879 | 1.14% | **0.004%** |

- **`Dst Port` 하나로 데이터가 거의 갈린다.** 53·443·123·137·138에 해당하는 약 138만 행
  (전체의 65.8%)이 공격 비율 1% 미만이고, 80·8080·21은 62~97%가 공격이다.
- 이는 프로토콜의 성질이 아니라 **테스트베드 배치가 피처에 새겨진 것**이다.
  실제 네트워크에서 80번 포트 트래픽의 62%가 공격일 수 없다.
  정상 트래픽 생성기가 주로 DNS·HTTPS로 나가고 공격이 주로 HTTP로 간 결과다.
- **8080번은 97.18%가 공격** — 피처가 아니라 사실상 라벨이다.
- CNS2022 Fig.1의 "공개판에서 `Dst Port`가 상위 피처였다가 재처리판에서 중요도 급감"도
  같은 현상의 반대편 증거다.

**부작용 — 논문에 공개해야 할 사항**

`Dst Port` 제외로 DNS·HTTPS라는 손쉬운 정상 신호가 사라져 **과제 난이도가 올라간다.**
난이도가 올라가면 확률이 덜 극단화되어 **우리가 찾으려는 유보 밴드가 채워질 가능성이 커진다.**
즉 이 결정은 **우리 실험에 유리한 방향으로 작용한다.**

**이것은 제외의 이유가 아니라 결과다.** 이유는 위의 누수이며,
부작용을 근거로 삼으면 결과에 맞춰 설계를 고른 것이 된다. **논문에 부작용으로 공개한다.**

**부수 효과:** 이 결정으로 구 정책 1-5가 종결된다. "3단계에서 재도입 여부 최종 결정"으로
이연했던 항목이 **"제외 확정, 재도입 없음"**이 되었다.
동시에 실시간 조기 피처 논의에서 **유일하게 구체적이던 후보가 사라졌다** —
조기 피처 경로가 필요해지면 처음부터 정의해야 한다.

### 5. 축 C — 부기 컬럼 (종결)

원본 91개 중 부기 컬럼은 **`id` 하나뿐이다.** 사유 코드는 `LEAK_TIME`이다(부기가 아니다).

요일 파일마다 1부터 재시작하며(원본 기준 검증: 고유값 547,557 = 금요일 행수),
요일 내 행 번호가 시각과 강하게 상관되므로 **`Timestamp`의 대리 변수로 작동**한다.
Timestamp를 제거해도 이것이 남으면 시간 누수가 유지된다.
사유 코드를 "부기"가 아니라 "시간 누수 대리"로 기록해야 재도입 논의가 생기지 않는다.

### 5-1. 축 D — 계산 오류 (종결, 2026-09-12)

**대상이 4개에서 6개로 확대되었다.** `Subflow Fwd/Bwd Bytes`는 초기 목록에 없었으나
진단 과정에서 같은 결함군임이 드러나 편입했다.

**(가) 헤더 길이 — 16비트 오버플로 (측정으로 확인)**

- 음수 발생: `Fwd` 309행(0.0147%, 범위 -32,708~-548), `Bwd` 472행(0.0225%, 범위 -32,764~-92).
- **가설 검정:** 음수 값에 65,536을 더하면 패킷당 헤더 바이트 중앙값이 `Fwd` 22.8 / `Bwd` 20.0이 되고,
  이는 정상(양수) 행의 `Fwd` 20.3 / `Bwd` 20.0과 일치한다. TCP 헤더 최소 20바이트와 부합.
- 값 범위가 `Fwd` -32,708~32,748 / `Bwd` -32,764~32,680으로 **signed 16비트 한계 안에 정확히 갇혀 있다.**
- **핵심 — 음수 검사만으로는 결함의 일부만 잡힌다.** 오버플로는 `mod 65,536` 순환이므로
  두 번 이상 감기면 값이 다시 양수가 되어 감지되지 않는다.
  패킷수×20 > 65,536인 행 중 `Fwd` 199행 가운데 **120행이 양수**, `Bwd` 262행 가운데 **155행이 양수**다.
  보수적 합산으로 오염은 `Fwd` 최소 429행, `Bwd` 최소 627행.
- **오염이 무작위가 아니다.** 오염 행의 패킷 수 중앙값이 1,894개로, 대량 패킷 플로우에 집중된다.

**보정(+65,536×k) 후 포함을 택하지 않은 이유:** `k`를 알 수 없고, 패킷 수로 역산하면
헤더 길이가 사실상 패킷 수의 결정론적 함수가 되어 독립 정보가 사라진다.
남는 정보인 "평균 헤더 크기"는 `Fwd Seg Size Min`이 부분적으로 담고 있어,
오염 위험을 감수할 만한 독립 가치가 없다.

**(나) Subflow Packets — 방향이 반전된 지시자 (예외 0건)**

- **`Subflow Fwd Packets == 1` ⟺ `Total Bwd packets == 0`** — 55,069행에서 예외 없이 일치.
- **`Subflow Bwd Packets == 1` ⟺ `Total Fwd Packet == 0`** — 33행에서 예외 없이 일치.
- 서브플로 패킷 수가 아니라 **"반대 방향에 패킷이 없음"** 지시자이며, 방향까지 뒤바뀌어 있다.
- 이미 피처인 `Total Fwd Packet`·`Total Bwd packets`의 결정론적 함수이므로 **독립 정보 0.**
- **부가 위험:** 이름이 의미를 오도한다. SHAP에 "Subflow Fwd Packets 중요"로 나오면
  "서브플로 구조가 중요하다"로 해석되지만 실제 뜻은 "역방향 패킷 부재"다.
  **XAI 연결부에서 잘못된 서술을 낳는다.**

**(다) Subflow Bytes — 총합이 아니라 평균 근사**

- 범위가 `Subflow Fwd Bytes` 0~1,777인데 대응하는 `Total Length of Fwd Packet`은 0~12,870,252.
  `Bwd`는 0~2,090 대 0~655,452,323. **3~4자릿수 차이.**
- `Fwd/Bwd Packet Length Mean`과의 상관 **0.9747 / 0.9808**. 사실상 평균 패킷 크기다.
- 평균과 완전 일치하는 비율은 15.3% / 13.6%에 그쳐 "평균의 잡음 섞인 중복"에 해당.
- `Packet Length Mean`·`Segment Size Avg`와 중복되어 **중요도가 분산되고 SHAP 해석이 흐려진다.**

**기록해 둘 점:** 오버플로 건은 **"음수를 찾는" 방식으로는 결함의 60~70%만 잡힌다.**
전수 조사에서 min 값을 확인했기에 발견되었으며, 통상적인 결측·이상치 검사만 돌렸다면 놓쳤을 항목이다.

### 5-2. 축 E — 분산 (종결, 2026-09-12)

**판단은 라벨 없이 수행했다**(확정 다). 구조적 통계와 컬럼의 의미만 사용.

**(가) `URG Flag Count`의 중복은 train 의존이 아니라 항등식이다**

구 파이프라인은 train 기준으로 이를 `Fwd URG Flags`와 "완전동일"로 판정했으나,
전역에서는 **단 1행**(`Bwd URG Flags`가 비영인 그 행) 때문에 달라진다.
즉 train에서 동일하게 보인 것은 우연이며, **실제 관계는 "동일"이 아니라 "합"**이다.
`URG Flag Count = Fwd URG Flags + Bwd URG Flags`가 2,099,976행 **전부**에서 성립한다.
항등식이므로 **분할과 무관하게 안정적인 제외 근거**다.

**(나) `NO_IMPACT`으로 제외한 4개 — 정보가 없어서가 아니다**

`Fwd URG Flags`(비영 93행), `Bwd URG Flags`(비영 1행), `CWR Flag Count`(764행),
`ECE Flag Count`(686행)는 **계산 결함이 아니며 의미론적으로도 유효**하다.
URG는 실재하는 TCP 플래그이고 비정상 플래그 조합은
스캐닝·회피 기법의 알려진 신호다(XMAS 스캔의 URG+PSH+FIN 등).
그럼에도 제외하는 이유는 **비영 행이 1~764개라 집계 지표를 측정 가능한 수준으로 움직일 수 없기 때문**이다.
`ECE Flag Count`의 비영 집합은 `CWR Flag Count`에 완전히 포함된다.

메모(판단 근거 아님): ECN 계열은 공격 탐지보다 **OS·네트워크 스택 지문**에 가까워
이 테스트베드에서는 환경 식별자로 작동할 여지도 있다. 라벨을 봐야 확인되므로 근거로 쓰지 않았다.

**(다) TCP 플래그 정보 자체는 유지된다**

`FIN Flag Count`(고유값 22), `SYN`(19), `RST`(66), `PSH`(647), `ACK`(2,318)와
방향별 `Fwd/Bwd PSH Flags`, `Fwd/Bwd RST Flags`가 모두 실질적 분산을 갖고 남는다.

**(라) Bulk 계열 6개 — 통과, 그리고 구 C-10 종결**

| 컬럼 | 비영 행 수 | 비영 비율 | 고유값 |
|---|---|---|---|
| `Fwd Bytes/Bulk Avg` | 86,979 | 4.14% | 4,569 |
| `Fwd Packet/Bulk Avg` | 86,979 | 4.14% | 98 |
| `Fwd Bulk Rate Avg` | 86,979 | 4.14% | 27,741 |
| `Bwd Bytes/Bulk Avg` | 291,647 | 13.89% | 45,451 |
| `Bwd Packet/Bulk Avg` | 291,647 | 13.89% | 822 |
| `Bwd Bulk Rate Avg` | 291,647 | 13.89% | 150,399 |

준상수가 아니라 **희소하지만 풍부**하다. "벌크 전송이 없으면 0"이라는 것 자체가 의미 있는 신호이며,
Fwd 3형제와 Bwd 3형제는 각각 **비영 집합이 완전히 동일**하다(같은 조건에서 함께 켜짐).

**이로써 구 로드맵 C-10이 종결된다.** "원본 문헌은 Bulk 계열 8개를 상수로 보고하는데 우리 결과는
훨씬 적다 — CNS2022가 버그를 고쳤을 가능성과 탐지 로직 누락 가능성이 둘 다 열려 있음"으로
보류했던 항목의 답은 **"CNS2022가 고쳤다"**이다. 원본 CSV에서 직접 세었고 고유값이 수만 개다.

**(마) 보류했던 제안이 이 컬럼들에 대해 해소된다**

"train 기준 상수/중복 판단이 분할에 따라 흔들린다"가 문제였고,
흔들리던 컬럼이 정확히 축 E의 5개였다. **whitelist에서 명시적으로 제외하면 흔들림 자체가 사라진다.**
자동 판단 로직은 잔여 케이스용 안전망으로만 남는다.

### 5-3. 축 F — sentinel 오독 (종결, 2026-09-12)

**대상은 `ICMP Type`·`ICMP Code` 둘뿐이다.** 남은 70개 컬럼을 전수 스캔한 결과
음수 최소값을 갖는 것은 이 둘이 유일했다.

- `-1`이 2,099,373행(99.9713%). `-1`은 "ICMP 아님"을 뜻하는 표식인데 트리는 이를 **수치로 취급**한다.
- **`ICMP Code ≠ -1` 집합 = `ICMP Type ≠ -1` 집합 = `Protocol == 1` 집합**, 예외 0건.
  "ICMP 여부"에 관해 `Protocol`과 **완전 중복**이다.
- 남는 독립 정보는 603행 내부의 Type/Code 세부뿐이다(Type 3 Code 3 = Port Unreachable 267행 등).
  의미론적으로는 유효하나 **축 E에서 `Fwd URG Flags` 93행, `CWR` 764행, `ECE` 686행을
  `NO_IMPACT`으로 제외한 것과 같은 자릿수**다. 603행만 남기면 기준이 흔들린다.

> **주의 — 이 제외는 `Protocol`이 포함임을 전제한다.**
> 두 컬럼의 제외 근거가 "`Protocol`과 완전 중복"이므로, `Protocol`을 빼면 ICMP 정보가
> 데이터에서 완전히 소멸하고 이 제외 근거도 성립하지 않는다. 두 결정은 함께 움직인다.

**방법론 정정 — 축 E의 스크리닝 기준**

축 E를 **"0 비율"**로 훑었으나, 지배값이 0이 아닌 컬럼은 걸러지지 않는다
(ICMP 계열의 지배값은 `-1`). 올바른 기준은 **"최빈값 비율"**이다.
재스크리닝 결과 실제 누락은 없었으나(99% 이상은 ICMP 둘뿐, 95~99%는 Bulk Fwd 3형제) 기준 자체를 정정한다.

### 5-4. 축 G — 실시간성 (범위 선언, 2026-09-12)

**이 축은 컬럼을 제외하지 않는다. 범위를 선언하는 축이다.**

생존 68개 중 첫 패킷에서 확정되는 것은 **`FWD Init Win Bytes`, `Bwd Init Win Bytes` 둘뿐**이며
(`Protocol` 포함 시 셋), 나머지 약 63개는 플로우 완결 후에야 값이 확정된다.

**확정 사항**

1. 이번 서브실험은 **실시간성을 검증하지 않는다.** 컬럼을 제외하지 않고 전량 사용한다.
2. 논문·보고서에 **"본 실험은 플로우 완결 후 피처를 사용하며 실시간 탐지 가능성을 검증하지 않았다"**를 명시한다.
3. 조기 피처 집합 정의는 본 연구로 이연한다.

**근거.** 이번 서브실험의 질문은 RQ1(유보 구간 식별)이지 실시간성이 아니다.
구 로드맵 A-4가 이미 "실시간 표현을 검증 없이 쓰지 않음"을 확정했으므로,
이 실험 결과로 실시간성을 주장하면 그 원칙을 어긴다.
또한 축 B에서 `Dst Port`를 제외하며 **조기 피처의 유일한 구체적 후보가 사라졌다.**

### 5-5. 축 H — 근사 중복 (종결)

축 A~G가 컬럼을 개별 판정하는 축이라면, 축 H는 **컬럼 쌍·집합의 관계**를 본다.

**왜 필요한가**

1. **SHAP 해석이 쪼개진다.** XAI 연결부에서 SHAP 기여도를 LLM 프롬프트에 직렬화하는데,
   같은 정보가 여러 컬럼에 나뉘면 중요도가 분산되어 실제로 중요한 신호가 프롬프트에 안 들어가거나,
   들어가더라도 같은 말을 반복하게 된다.
2. **시드 간 변동이 커진다.** 트리는 중복 피처 중 하나를 임의로 골라 분기한다.
   다중 시드로 **유보 밴드 비율의 분산**을 볼 계획이므로 직접 걸린다.
3. 모델 성능 자체에는 큰 피해가 없다. **문제는 해석과 안정성이다.**

#### 5-5-1. 판정 방법 확정 — Spearman + 3중 보정

**기본: Spearman(순위상관).** LightGBM은 분기 시 "이 값이 X보다 큰가"만 묻고 **순서만 사용**하므로,
"두 컬럼이 트리에게 같은 정보인가"는 곧 "순서가 같은가"이다.

- **보정 1 — 둘 다 비영인 행으로 한정.** 두 컬럼이 모두 대부분 0이면 그 행들이 순위에서 동점이 되어 상관이 부풀려진다.
- **보정 2 — 통계 가족은 해당 Std > 0인 행으로 한정.** Mean/Max/Min은 원소가 1개면 정의상 같은 값이 되어 동점이 발생한다.
- **보정 3 — 다변량 항등식은 별도 확인.** `A = B ÷ C` 같은 관계는 쌍별 상관이 모두 낮아도 성립한다. **상관계수만으로는 검출 불가.**

**임계값: 보정 후 |ρ| ≥ 0.95**

#### 5-5-2. 방법론 보정 이력 — 5건

| # | 오류 | 원인 | 구체 증거 | 발견 계기 |
|---|---|---|---|---|
| 1 | Pearson 사용 | 두꺼운 꼬리 — 거대값 소수가 지배 | `Total Length of Bwd Packet ↔ ACK Flag Count`: Pearson +0.9957 → Spearman **+0.5625** | 자체 교차검증 |
| 2 | 단조변환 미탐지 | Pearson이 비선형 단조관계를 못 잡음 | `Packet Length Std ↔ Variance`: Pearson 0.96 → Spearman **1.0000** | 자체 교차검증 |
| 3 | 공통 희소성 | 0인 행이 순위에서 동점 | `Bwd Packet/Bulk Avg ↔ Bwd Bulk Rate Avg`: 전체 +0.9893 → 비영 **-0.5583** (부호 반전) | **사용자의 "대표 후보" 질문** |
| 4 | 구조적 동점 | 원소 1개면 Mean=Max=Min | `Idle Mean ↔ Idle Max`: 0.9569 → Std>0 한정 **0.7731** | **사용자의 "하나씩 진행" 지시** |
| 5 | 다변량 항등식 미검출 | 쌍별 상관으로는 3변량 결정관계를 못 봄 | `Down/Up Ratio = Bwd ÷ Fwd` 100.00%인데 쌍별 ρ는 모두 0.95 미만 | 군집 7 개별 검토 |

**보정 3(공통 희소성)의 영향이 가장 컸다.** |ρ|≥0.95인 65쌍 중 **19쌍이 가짜**로 판명되었고,
**Bulk 군집 2개와 Active/Idle 대군집이 통째로 해체**되었다.
보정 전 초안에서 "Bulk 3형제는 최소 ρ 0.9997이니 1개면 충분"이라고 판단했으나
**비영 기준으로는 0.52~0.62로 서로 다른 정보였다.**

**교훈: 상관계수는 "같은 값이 반복되는 구조"에 부풀려진다.
희소성·구조적 동점·다변량 관계를 각각 확인하기 전에는 중복으로 판정하지 말 것.**

#### 5-5-3. 정책 P-DIR — 방향별 우선 (확정)

> **방향별(Fwd/Bwd)과 이를 집계한 컬럼(합계·최솟값·최댓값·가중평균)이 함께 있을 때,
> 방향별을 남기고 집계를 제외한다.**

**근거.** 집계는 방향별에서 복원되지만 역은 불가능하다.
트리가 집계값으로 편해지는 이점(트리는 나눗셈·min·가중평균을 직접 계산하지 못함)은 인정하되,
**정보 소실보다 우선하지 않는다.**

**정책의 취지는 "방향별 정보의 보존"이다(사용자 확정).**
따라서 `Down/Up Ratio`처럼 **방향 관계 자체를 담는 파생 컬럼은 P-DIR의 제외 대상이 아니다** —
방향 정보를 뭉개는 집계(합계·최솟값)와 달리 방향 비대칭을 보존하기 때문이다.

**예외 조건.** 방향별 둘 중 하나가 이미 다른 사유로 제외된 경우에는 이 원칙이 성립하지 않는다.
그때는 집계를 남긴다.

#### 5-5-4. 응집 군집 처리 결과 (종결) — 8개 제외

| 군집 | 최소 비영ρ | 처분 |
|---|---|---|
| **H-09** | 1.0000 | `Fwd Packet Length Mean` 포함 / `Fwd Segment Size Avg` 제외 |
| **H-08** | 0.9996 | `Fwd Packet Length Min` 포함 / `Packet Length Min` 제외 |
| **H-10** | 0.7731 | **해체** — `Idle Mean`·`Idle Max` 둘 다 포함 |
| **H-07** | 0.9800 | `Total Fwd Packet`·`Down/Up Ratio` 포함 / `Total Bwd packets` 제외 |
| **H-02** | 0.9831 | `Bwd Packet Length Max`·`Packet Length Std` 포함 / `Packet Length Max`·`Packet Length Variance` 제외 |
| **H-03** | 0.9682 | `Bwd Packet Length Mean` 포함 / `Packet Length Mean`·`Average Packet Size`·`Bwd Segment Size Avg` 제외 |

**H-09** — `Fwd Packet Length Mean` = `Fwd Segment Size Avg`, 최대 절대차 3.4e-12.
`Fwd Packet Length Mean == 총길이 ÷ 패킷수`가 100.0000%.
대표 선정 근거: **이름-내용 일치.** "Segment Size"는 TCP 세그먼트라는 다른 개념을 암시하나
실제 값은 패킷 길이 평균이다(축 D의 `Subflow` 사례와 동종). `Max/Min/Mean/Std` 이름 체계 일관성도 근거.

**H-08** — 역방향 패킷이 있는 행에서 `Packet Length Min == min(Fwd, Bwd)` **99.9998%**.
`Bwd Packet Length Min`은 단독으로 생존하므로 방향별이 완비된다. **P-DIR 최초 적용 사례.**
`Packet Length Min ↔ Fwd Packet Length Min` 불일치는 5,768행(0.27%)뿐이라
트리가 집계값으로 얻는 이점도 그 규모에 그친다.

**H-10 — 해체.** 유휴 구간이 정확히 1개인 행이 유휴 보유 행의 **52.82%**이며
그 행들은 Mean=Max=Min이 정의상 같다. 구간이 2개 이상인 **220,390행(10.49%)**으로 한정하면
ρ가 **0.7731**로 떨어진다. 220,390행은 `NO_IMPACT` 기준으로도 충분히 크다.

**H-07** — `Down/Up Ratio = Total Bwd packets ÷ Total Fwd Packet`이 오차 1e-6 내 **100.00%**.
세 컬럼 중 둘만 있으면 충분하다. `Total Fwd Packet`(규모) + `Down/Up Ratio`(비대칭)로
**개념적으로 직교하는 두 축**을 남긴다. `Total Fwd Packet`을 규모 기준으로 택한 이유는
0인 행이 33개뿐으로 정의가 안정적이고(Bwd는 55,069개) 순방향이 공격자→피해자 방향이기 때문.
비대칭 분포: 62.20%가 비율 정확히 1.0, 2배 이상 비대칭은 0.69%, 단방향 플로우 55,069행.

**H-02** — 항등식 2개. `Packet Length Variance = Packet Length Std²`(최대 상대오차 1.2e-15),
`Packet Length Max = max(Fwd Max, Bwd Max)`(**100.0000%, 예외 0건**, P-DIR 적용).
`Packet Length Max == Bwd Max`가 93.94%인데 `== Fwd Max`는 23.82% —
**플로우 최대 패킷은 거의 항상 역방향(서버 응답)에서 나온다.**
그래서 `Fwd Packet Length Max`는 이 군집과 무관하며(비영ρ 0.4970) 단독 생존한다.
`Packet Length Std`는 유지 — 방향별 Std로 **복원되지 않고**(근사 상관 0.8624,
Fwd Std와 0.7275 / Bwd Std와 0.8605), `Bwd Packet Length Max`와의 0.9729는
극값과 퍼짐이라는 **다른 개념이 같은 원인(역방향 큰 패킷)에 반응한 결과**다.

**H-03** — 항등식 3개. 이름 쌍 2개(`Packet Length Mean`=`Average Packet Size` 6.9e-11,
`Bwd Packet Length Mean`=`Bwd Segment Size Avg` 9.8e-11)와
**가중평균 항등식** `Packet Length Mean = (FwdMean×FwdCnt + BwdMean×BwdCnt) ÷ 총패킷수` **100.0000%**.
재료가 전부 포함 확정이므로(Fwd Mean, Total Fwd Packet, Down/Up Ratio) P-DIR 적용.
**`Fwd Mean ↔ Bwd Mean`은 0.0942로 사실상 독립**이며, 전체 평균은 역방향에 끌려간다(0.9690).
그 결과 `Packet Length Mean`을 빼도 `Bwd Packet Length Mean`이 거의 같은 분기를 제공하므로
**트리 측 손실도 없다.**

#### 5-5-5. 느슨 군집 — H-06만 처리, 나머지는 이연

**H-06 처리 (확정).** `PSH Flag Count` = `Fwd PSH Flags` + `Bwd PSH Flags`가 **100.0000%, 불일치 0행**.
쌍별 상관(0.9642 / 0.9640 / 0.8933)으로는 판정 불가였고 **보정 3(다변량 항등식)** 적용으로 발견했다.

P-DIR 재검토(사용자 지시)를 수행한 결과 **세 조건 모두 부합**했다.
① 방향별 값이 다른 행이 **46.6%** (둘 다 비영인 774,267행 중 값이 같은 건 53.4%뿐),
Fwd만 비영 15,580행 / Bwd만 비영 4,100행 → **방향 비대칭이 실재**.
② 합계는 항등식으로 복원되나 역은 불가 — `Count=10`이 Fwd 7/Bwd 3인지 3/7인지 알 수 없다.
③ 덧셈은 트리가 근사 가능하며(min·나눗셈보다 쉬움), 합계↔방향별 상관 0.964로 분기도 거의 대체된다.

→ `PSH Flag Count` 제외, `Fwd PSH Flags`·`Bwd PSH Flags` 포함.

**추가 항등식 1건 (확정).** `Flow Packets/s` = `Fwd Packets/s` + `Bwd Packets/s` **100.0000%**.
H-06과 동일 구조(덧셈 + P-DIR)이므로 `Flow Packets/s` 제외.

**나눗셈 항등식은 적용하지 않는다.** `Flow IAT Mean` = Duration ÷ (총패킷−1),
`Fwd/Bwd IAT Mean` = Total ÷ (패킷수−1), `Fwd Packets/s` = 패킷수 ÷ Duration 모두 100% 성립하나,
**나눗셈은 트리가 만들 수 없는 형태**이므로 H-07(`Down/Up Ratio` 유지)의 선례를 따라 **전부 유지**한다.
`Flow IAT Mean ↔ Fwd Packets/s`가 -0.9957로 근사 대체재가 있으나,
이를 근거로 제외하면 **임계값 판단**이 되어 §5-5-6의 이연 원칙과 충돌한다.

**H-01·H-04·H-05는 처리하지 않는다.** 사유는 §5-5-6.

#### 5-5-6. 축 H의 자기 평가 — 상관 기반 판정은 모델 이후로 이연 (확정)

**관찰 — 축 H의 제외 10건은 전부 항등식이 결정했다. 상관계수가 단독으로 결정한 사례는 0건이다.**

`Packet Length Std`를 **유지**한 근거도 같은 논리의 반대편이었다 — 상관 0.9729로 높았으나
**항등식이 없어서** 남겼다. 즉 실제 규칙은 **"항등식이 있으면 제외, 없으면 유지"**였고,
**상관계수는 어디를 들여다볼지 알려주는 손전등**이었을 뿐이다.

**군집은 분석 단위가 될 수 없다.** 군집은 상관 측정법 + 임계값 + 연결 규칙의 산물이며,
이 작업에서만 **네 번 구성이 바뀌었다**(Pearson→Spearman, 희소성 보정, 동점 보정, 임계 0.95/0.97/0.99).
Bulk 군집과 Active/Idle 대군집은 통째로 사라졌다.
**네 번 모양이 바뀌는 것은 데이터의 성질이 아니라 측정 방식의 성질이다.**
반면 항등식은 측정법과 무관하게 참이다.

→ **기록 규칙: 사유란에는 군집 번호가 아니라 항등식 자체를 적는다.**
군집 ID(H-0X)는 "어떻게 발견했는지"의 출처 각주로만 남긴다.

**확정 — 상관 기반 제외는 하지 않는다.**

항등식이 없는데 상관만 높은 쌍(예: `Flow Duration ↔ Flow IAT Max` 0.9808)은 **제외하지 않는다.**
"0.98이면 중복"은 임계값 선택이며, 이 작업에서 네 번 틀린 바로 그 방식이다.
**축 H의 목적(SHAP 분산, 시드 간 변동)은 애초에 모델을 돌려야 측정되는 것**이므로,
대표만 쓴 것과 전부 쓴 것의 **유보 밴드 비율·시드 간 분산을 비교해 실측으로 판단**한다.
이로써 이 단계에서 추측으로 정하는 것이 0이 된다.

#### 5-5-7. baseline(CNS2022) 대조 — 우리가 무엇을 다르게 했는가

**CNS2022 §IV-C-1 원문:**
> For all datasets, we first drop flow-identifying columns. We also drop columns that are strongly
> correlated with others, determined by using Pearson correlation, with a coefficient of 0.9 as the threshold.

**baseline의 피처 선택은 두 단계가 전부다.**
① flow-identifying 제거 (§IV-A-3 목록: `Flow Id, Source IP, Source Port, Destination IP, Timestamp`)
② **Pearson |r| ≥ 0.9** 상관 제거

| baseline | 우리 | 차이의 근거 |
|---|---|---|
| flow-identifying 5개 | 축 A·B·C — `Dst Port`·`id` 추가, `Protocol` 인코딩 | **`Dst Port`는 baseline 목록에 없어 그들은 피처로 남겼다.** 우리가 제외한 근거는 그들 자신의 Fig.1("공개판에서 Dst Port 상위 피처 → 재처리판에서 중요도 급감")과 우리 측정(80번 62%·8080번 97% 공격) |
| **Pearson ≥ 0.9** | **상관 기반 제거 안 함** | Pearson은 두꺼운 꼬리에 지배된다. `Total Length of Bwd Packet ↔ ACK Flag Count`가 Pearson +0.9957인데 Spearman +0.5625 — 임계 0.9에서는 허위 검출이 더 많아진다 |
| 없음 | 축 D (계산 오류) | **상관으로는 검출 불가.** 16비트 오버플로, `Subflow*`의 방향 반전은 값의 의미를 봐야 나온다 |
| 없음 | 축 E·F | 실질 효과는 작으나(93~764행) 기준 일관성을 위해 수행 |
| 없음 | 축 G (범위 선언) | 실시간성 미검증을 명시 |

**목적이 다르다는 점도 기록한다.** CNS2022의 피처 선택은 **데이터셋 버전 간 피처 중요도 비교**를 위한
전처리였다(Random Forest로 피처를 하나씩 빼며 F1 변화 측정). 우리는 **확률 분포와 유보 밴드를 재는
게이트**를 만든다. SHAP 결과를 LLM 프롬프트에 직렬화하므로 **이름-내용 불일치**가 실제 해가 되고
(`Subflow*`, `Segment Size Avg`), 유보 밴드 측정은 **인위적으로 쉬운 피처에 F1보다 훨씬 민감**하다.

**자기 평가 — 축 H의 상관 군집화는 과했다.** 제외 10건이 전부 항등식으로 결정된 이상,
**항등식을 직접 찾았으면 훨씬 빨랐다.** baseline이 Pearson 0.9로 넘어간 자리에서 우리는
그 방법이 왜 틀렸는지 증명하는 데 시간을 썼고, 증명 자체는 유효하나 그 길에 들어설 필요는 없었다.
**반면 축 A~D는 정당했다** — baseline의 방법으로는 검출 불가능한 결함을 찾았기 때문이다.

### 6. `Protocol` — 포함 + 인코딩 처리 (확정)

> **주의 — 이 항목은 과거 요약본에서 "제외 확정"으로 잘못 기록된 적이 있다.**
> `Protocol`은 **포함**이며 `configs/features_whitelist.json`의 `include`에 있다.
> "정수 매핑이 서열로 오독됨"은 **제외 사유가 아니라 해결해야 할 문제의 진술**이고,
> 그 해결책이 아래의 인코딩이다. 상세: `docs/doc_consistency_audit_2026-09-13.md` §A-1.

`Protocol`은 축 B에 해당하지 않는다. 누수가 아니며 실제 운영 환경에서도 일반화되는 정당한 피처다.
**포함하되 인코딩 처리가 필요하다.**

**문제:** 범주형인데 정수로 저장되어 트리 모델이 `6 < 17`을 순서 관계로 취급한다.
TCP와 UDP 사이에 순서는 없다.

**확정된 매핑**

| 원값 | 행 수 | 범주 | 성격 |
|---|---|---|---|
| 6 | 1,098,771 | `TCP` | 정상 |
| 17 | 999,092 | `UDP` | 정상 |
| 1 | 603 | `ICMP` | 정상 (CNS2022 신규 지원) |
| 0 | 1,510 | **`UNKNOWN`** | **TSO 아티팩트 표식** |

**`0`을 "기타"로 묶지 않는 이유 (측정 근거)**

`Protocol=0`인 1,510행은 **예외 없이 전부 `Src Port=0`이고 `Dst Port=0`이다.**
이는 CNS2022가 기술한 TSO 오류의 흔적과 정확히 일치한다 —
"TSO 패킷이 원래 플로우에 배정되지 못하고 **출발지·목적지 포트가 0인 별도 플로우('unknown payload')로 분리**된다."
즉 `Protocol=0`은 프로토콜이 아니라 **플로우 구성 실패 표식**이다.
"기타"로 부르면 "다른 프로토콜"로 읽혀 이 의미가 사라지므로 `UNKNOWN`으로 둔다.

반면 `Protocol=1`(ICMP) 603행은 정상이다. ICMP는 포트가 없으므로 포트 0이 당연하며,
`ICMP Type`도 3(Destination Unreachable) 434 / 8(Echo Request) 119 / 0(Echo Reply) 41 /
11(Time Exceeded) 9로 의미 있게 분포한다.

**구현 요구사항:** 문자열 치환만으로는 해결되지 않는다.
LightGBM은 문자열을 직접 받지 않으므로 pandas `category` dtype으로 변환한 뒤
**`categorical_feature`로 명시 선언**해야 한다. 선언을 빠뜨리면 내부 코드값으로 다시 순서 취급된다.

**문자열 매핑의 부가 가치:** XAI 연결부에서 플로우를 구조화 텍스트로 직렬화해 LLM 프롬프트에 넣을 때
`Protocol=6`보다 `Protocol=TCP`가 낫고, SHAP 결과 판독에도 유리하다.
**본 연구 2차 계층 설계와 직접 맞물린다.**

### 7. 최종 whitelist

**원본 91개 = 포함 59개 + 제외 32개. 미분류 0개.**

**목록은 `configs/features_whitelist.json`에 있다. 이 문서는 목록을 복제하지 않는다.**
각 제외 항목에 `code`(사유 코드)·`axis`(판단 축)·`reason`(근거)이 부여되어 있다.

#### 7-1. 구현 요구사항

1. 학습 코드는 `configs/features_whitelist.json`을 읽어 입력 컬럼을 구성한다.
   목록을 코드에 하드코딩하지 않는다.
2. **검증 항목 3개** (오류 4의 교훈 — 검증 없는 정책은 지켜지는지 알 수 없다). **전부 미구현.**
   - 학습 입력의 컬럼 집합이 whitelist의 `include` 목록과 **정확히 일치**
   - 원본 91개 전 컬럼이 `include` 또는 `exclude` 중 하나로 분류되어 **미분류 0개**
   - `exclude` 목록의 컬럼이 학습 입력에 **0개** 존재
3. **`Attempted Category`는 데이터에 보존**한다(whitelist 제외 ≠ 삭제).

5. `Protocol`은 §6의 인코딩 지시를 따른다.

## D-004. 분할 프로토콜

**최초 확정:** 2026-09-13

**개정:** 2026-09-14 — 59-feature 완전일치 중복·class overlap 실측 반영

**후속 개정:** 2026-09-15 — EXP-007 결과 이후 분할 seed 민감도 분석 허용
**선행:** D-001, D-002, D-003

### 1. 질문

1,929,529행(D-001·D-002 적용 후)을 어떤 규칙으로 학습·평가로 나눌 것인가.

### 2. 결정

```
대상 1,929,529행
  ├─ train 1,447,147행
  └─ test    482,382행   ← 한 번만 평가
```

1. **주 분석은 59-feature 완전일치 그룹 기반 2분할이다.**
   `configs/features_whitelist.json`의 `include` 59개 값이 전부 같은 행은 하나의 배정 단위로 묶고,
   그룹 전체를 train 또는 test 한쪽에만 둔다. `Protocol`은 D-003의 범주 매핑을 적용한다.
   중복 행은 삭제하지 않는다.
2. **계층화 기준은 원래 공격 종류(`Label`)다.** 이진 라벨이 아니다.
   그룹을 쪼개지 않는 제약 안에서 라벨별 test 25%에 가장 가깝게 결정론적으로 배정한다.
   seed는 **42**다.
3. **정상·공격 class overlap 그룹도 쪼개지 않는다.** 삭제하거나 별도 관찰군으로 옮기지 않고
   학습·평가 대상에 유지한다. 단, test에 배정된 class overlap 행의 오류율·예측 확률 분포·유보율은
   전체 지표와 별도로 보고한다.
4. **행 단위 `Label` 계층 랜덤 75:25 분할은 낙관적 민감도 분석으로만 실행한다.**
   주 분석과 같은 모델·피처·하이퍼파라미터를 사용하고 분할만 바꾼다. 주 분석 결과를 대체하거나
   독립 test 성능으로 해석하지 않는다.
5. **calibration set 없음, 교차검증 없음.** 이 실험은 확정된 confidence의 순위와 동률에 따른
   risk-coverage를 평가하고, 유보 밴드는 test 예측 확률을 전량 저장해 **오프라인으로 스윕**하므로
   확률 보정을 수행하지 않는다.
   ECE/Brier는 이 실험 범위 밖이다.
6. test 예측 확률을 **전량 파일로 저장**한다. 임계값을 사전에 고정하지 않는다.
7. 관찰군 2종(D-001 Attempted, D-002 DoS Hulk)은 train/test 어느 쪽에도 배정하지 않는다.
8. **후속 실험에서 완전일치 그룹 분할의 seed 민감도 분석을 허용한다.** EXP-007의
   `group_seed42` 주 분석과 그 성공 판정은 변경하지 않는다. 후속 실험은 실행 전에 seed 집합,
   동일한 그룹·원래 `Label` 계층화·75:25 규칙, 모델 고정 방식, 성공/실패/판정불가 기준을
   별도 스펙에 고정한다. 새 분할은 같은 원본 행을 재배정한 **구조적 민감도 분석**으로만
   해석하며 독립 데이터셋 재현이나 희소 클래스별 seed 변동성 추정으로 주장하지 않는다.
9. **EXP-008의 판정은 오류 순위와 고정 유보 경계의 실제 처리량을 별도로 한다.**
   두 결과를 하나의 실패 사유로 합치거나 한쪽의 성공으로 다른 쪽의 실패를 덮지 않는다.
   각 판정의 수치 기준과 혼합 결과의 전체 해석은 실행 전 별도 실험 스펙에서 확정한다.
   (사용자 확정: 2026-09-15.)

**해석 규칙(실행 전 고정).** 주 분석은 동일한 59-feature 값을 train에서 본 test 행이 없도록 한다.
행 단위 랜덤 민감도 분석은 test의 동일-feature 누수로 인해 모델에 유리한 조건이다. 두 결과의 차이는
중복 누수가 확신도·AURC·유보율에 미친 영향으로 해석한다. 어느 분할에서도 유보 구간이 발견되지 않으면
"존재하지 않는다"가 아니라 **"해당 분할 조건에서는 관찰되지 않았다"**까지만 결론 낸다.

### 3. 근거

#### 3-1. 다른 분할 방식을 왜 채택하지 않았는가

| 방식 | 판정 | 근거 |
|---|---|---|
| Temporal (시간 분할) | 붕괴 | CIC-IDS2017은 공격이 요일별로 배치됨. 실측: **13개 클래스 중 2개만 test에 생존**, 전 모델 macro-F1 ≈ 0.50 |
| 5-tuple group 분할 | 랜덤과 사실상 동일 | src port가 매번 바뀌어 그룹당 평균 ~2행(146만 그룹 / 283만 flow). 실측: RF macro-F1 0.769 → **0.778로 오히려 상승** |
| Campaign group 분할 | 공격 클래스 holdout으로 붕괴 | 우리 측정상 대부분 공격이 1 src → 1 dst → 연속 시간구간. campaign ≈ 라벨 자체 |

**주의:** 이 논문은 원본 공개판(2,827,677 flows)을 쓰며 개선 라벨을 쓰지 않는다.

근본 원인 절(대부분의 공격이 공격자 IP 1개 → 피해자 IP 1개 구조).

#### 3-2. 75:25 비율의 출처

Engelen et al., WTMC 2021 원문에 "We used a train-test split of 75-25." 확인됨.

**주의 2건.**
- 이 논문의 분류기는 **Random Forest**이고 평가가 **per-class**이다.
  비교 가능성을 주장하려면 우리도 클래스별로 산출해야 한다.
- **CNS2022는 고정 split을 규정하지 않았다.** "CNS2022 공식 split"이라고 쓰면 안 된다.

#### 3-3. 구 그룹 분할이 실패한 원인 (반복 방지용 기록)

구 2단계 설계는 그룹 키를 `hash(src_ip, dst_ip, attack_label, floor(ts/300))`으로 두었고,
`min_group_count_for_split=10` 미달 레이블을 전량 test로 배정했다.

- 근본 원인은 임계값 10이 아니다. **`src_ip`·`dst_ip`가 분해력을 갖지 못해
  그룹 키가 사실상 시간 버킷 하나로 축소**되었다.
- 그 결과 그룹 수 ≈ 공격 지속시간 ÷ 버킷 크기. DoS Hulk 1,091초, DDoS 1,179초짜리 공격이라
  300초 버킷에서 구조적으로 5개만 나온다.
- **공격 규모가 클수록 학습에서 빠지는 역설적 구조**가 되어, train 공격의 95.7%가 Portscan 계열,
  calib 공격 비율 6.81% vs test 48.50%(사전확률 7배 차이)라는 결함을 낳았다.
- 상세: `docs/dataset_audit_2026-09-11.md` §2-3.

**이 진단은 그룹 기반 분할을 재검토할 때만 참조한다. 현재 채택안의 전제가 아니다.**

#### 3-4. 59-feature 완전일치 중복·class overlap 실측

출처: `reports/class_overlap/` 및 `reports/split_feasibility/` (2026-09-14).

- 학습·평가 대상 1,929,529행 중 완전일치 중복은 **62,352그룹, 444,235행(23.02297607%)**이다.
- 정상·공격 이진 라벨이 충돌하는 완전일치 그룹은 **15개, 2,705행(0.14018965%)**이다.
- 행 단위 계층 랜덤 분할에서는 test 482,382행 중 **106,139행(22.00310128%)**의 59-feature 값이
  train에도 존재한다. 이 중 106,126행은 동일한 원래 `Label`까지 train에 존재한다.
- 완전일치 그룹 기반 분할은 정확히 train 1,447,147행 / test 482,382행을 만들면서
  train/test 교차 그룹 **0개**, 양쪽에서 소멸한 라벨 **0개**를 달성한다.
- 희소 클래스도 양쪽에 남는다: Heartbleed 8/3, Infiltration 27/9,
  Web Attack - Brute Force 55/18, SQL Injection 10/3, XSS 14/4 (train/test).

따라서 행 단위 랜덤 분할을 주 분석으로 유지하면 test 독립성이 크게 훼손된다. 반면 완전일치 그룹
기반 분할은 D-005의 희소 클래스 보고 조건과 75:25 비율을 유지할 수 있어 주 분석으로 채택한다.

### 4. 결과적으로 따라오는 영향

- 구 파이프라인의 `split`·`group_id`·`original_split`·`below_min_group_count` 필드는 전부 무효다.
- calib split이 없으므로 보정 관련 코드 경로 전체가 이 실험에서 실행되지 않는다.
- 주 분석의 split 산출물은 데이터 SHA256, seed, 행 수, 라벨별 train/test 수와 함께 고정한다.
- 주 분석 실행 전 검증은 완전일치 그룹 교차 0개, 관찰군 혼입 0개, 모든 원래 라벨의 양쪽 생존을
  강제한다. 하나라도 실패하면 학습을 시작하지 않는다.
- 행 단위 랜덤 분할은 민감도 분석 전용이며, 동일-feature 누수량을 결과에 병기한다.
- class overlap 행은 전체 결과에 포함하되 별도 부분집합 지표를 함께 낸다.

## D-005. 희소 클래스 정책

**확정일:** 2026-09-13
**선행:** D-004

### 1. 질문

플로우 100개 미만인 레이블(Heartbleed 11, Web SQLi 13, Web XSS 18, Infiltration 36, Web BF 73)을
어떻게 취급할 것인가.

### 2. 결정

- 오버샘플링·복제·삭제 **하지 않는다.**
- seed 반복으로 변동폭을 재지 **않는다.**
- **보고 규칙:** 클래스별 지표에는 test 표본 수를 반드시 병기한다
  (예: `Heartbleed recall 0.667 (n=3)`).
- **소표본 클래스에 대해 성능 주장을 하지 않는다.**

### 3. 근거

- D-004의 계층화(`Label` 기준)로 이 클래스들도 test에 최소 몇 건은 들어간다.
  따라서 "아예 평가되지 않는" 문제는 해소된다.
- 그러나 test 표본이 3~18건 수준이면 recall 한 칸의 이동이 지표를 크게 흔든다.
  표본 수를 병기하지 않은 수치는 **읽는 사람을 오도한다.**
  `docs/dataset_audit_2026-09-11.md` §1 오류 2가 같은 유형의 사례를 기록한다
  (GWO-LightGBM 논문이 Infiltration 36샘플·DoS-GoldenEye 16샘플에서 100%를 기록하고
  저자 본인이 "샘플 수가 극히 적어서"라고 인정한 건).
- seed 반복을 하지 않는 이유는 **표본이 작아 변동이 자명하기 때문**이다.
  측정해도 "작은 표본이라 흔들린다"는 이미 아는 사실만 확인하게 된다.

### 4. 결과적으로 따라오는 영향

- 클래스별 지표 테이블의 스키마에 `n_test` 컬럼이 필수가 된다.
- 논문·보고서에서 이 클래스들을 근거로 한 주장을 할 수 없다.

### 5. 미결

- 없음. 단 LOAO를 도입하게 되면 이 정책은 재검토 대상이다.

## D-006. 학습·평가 프로토콜과 판정 기준 — **확정 진행 중**

**착수:** 2026-09-14
**선행:** D-003, D-004, D-005

실행 **전에** 성공/실패/판정불가 기준을 수치로 확정해야 한다. `experiments/TEMPLATE.md` §4 요구사항.
결과를 본 뒤 기준을 정하면 사후 합리화가 된다.

### 1. 질문

LightGBM을 어떤 손실로 학습하고, 어느 지표로 학습 길이를 선택하며, 완성된 모델이 유보 구간의
존재를 보여 주는지는 어느 지표로 판정할 것인가.

### 2. 현재까지 확정한 결정

1. **학습 목적함수는 무가중 binary log loss다.** 기본 실험에서는 class weight,
   `scale_pos_weight`, `is_unbalance`, 표본 가중치를 사용하지 않는다.
2. **Early stopping은 외부 train 안에서 분리한 내부 validation의 binary log loss 하나만 사용한다.**
   여러 지표를 기록하더라도 학습 중단에는 이 지표만 관여하도록 `first_metric_only=true`를 명시한다.
   내부 분할 비율과 구성 규칙은 아직 미확정이다.
3. **최종 주 지표는 외부 test의 AURC다.** 낮을수록 좋다. confidence 정의, 동률 처리,
   risk-coverage 곡선 및 적분 규칙은 실행 전에 별도로 확정한다.
4. **보조 지표 범위는** 사전 지정한 유보 budget별 selective risk, error capture, FPR, FNR,
   AUROC, AUPRC로 한다. budget 지점과 각 지표의 정확한 계산 규칙은 아직 미확정이다.
5. 가중 binary log loss와 focal loss는 기본 실험에 넣지 않는다. 기본 결과 이후 필요성이 확인되면
   별도 후속 실험으로만 검토한다.
6. **포함 피처 `Flow Bytes/s`의 ±Infinity는 NaN으로 변환한다.** 행은 삭제하지 않고,
   별도 결측 indicator 피처도 추가하지 않는다. LightGBM은 `use_missing=true`,
   `zero_as_missing=false`로 두어 NaN만 결측으로 취급한다. 변환 후 전체 모델 입력에서 ±Infinity가
   0건인지 강제 검증하고, 변환된 행 수와 외부 split별 행 수를 실행 manifest에 기록한다.
   +Infinity가 존재하지만 whitelist에서 제외된 `Flow Packets/s`는 모델 입력 전처리 대상이 아니다.
7. **외부 train은 early stopping을 위해 내부 train/validation 75:25로 한 번만 분할한다.**
   D-004와 동일하게 59-feature 완전일치 그룹을 배정 단위로 하고 원래 `Label` 기준으로 근사
   계층화하며 seed 42를 사용한다. 동일 그룹의 내부 train/validation 교차는 0개여야 하고,
   외부 train에 존재하는 모든 원래 `Label`이 양쪽에 생존해야 한다. 정확한 행 수는 그룹 제약을
   적용한 분할 산출물에서 확정한다. 이는 calibration set이나 교차검증이 아니다.
8. 내부 validation에서 선택한 `best_iteration`은 외부 test를 보기 전에 고정한다. 이후 내부
   train과 validation을 합친 외부 train 전체로 같은 전처리·하이퍼파라미터와 고정된
   `best_iteration`을 사용해 최종 모델을 재학습한다.
9. **LightGBM 하이퍼파라미터는 실행 전에 고정한 최대 8개 후보의 제한된 격자에서 선택한다.**
   모든 후보는 같은 내부 train/validation, 무가중 binary log loss, seed를 사용하고 각 후보별로
   validation binary log loss 기반 early stopping을 수행한다. 후보 선택 기준은 최저 validation
   binary log loss이며 외부 test의 AURC나 보조 지표는 선택에 사용하지 않는다. 후보 집합,
   동률 처리 및 정확한 seed 설정은 다음 결정에서 고정한다. 광범위한 grid/random/Bayesian search와
   실행 후 후보 추가는 하지 않는다.
10. **제한 격자는 아래 8개로 고정한다.** 후보 식별자는 `candidate_id`이며 정의처는
    `docs/glossary.md`다.

    | `candidate_id` | `num_leaves` | `min_data_in_leaf` | `lambda_l2` |
    |---|---:|---:|---:|
    | `C01` | 31 | 20 | 0.0 |
    | `C02` | 31 | 20 | 1.0 |
    | `C03` | 31 | 200 | 0.0 |
    | `C04` | 31 | 200 | 1.0 |
    | `C05` | 63 | 20 | 0.0 |
    | `C06` | 63 | 20 | 1.0 |
    | `C07` | 63 | 200 | 0.0 |
    | `C08` | 63 | 200 | 1.0 |

11. 모든 후보의 공통값은 `boosting_type=gbdt`, `objective=binary`,
    `metric=binary_logloss`, `learning_rate=0.05`, `max_depth=-1`, `feature_fraction=1.0`,
    `bagging_fraction=1.0`, `bagging_freq=0`, `max_bin=255`, `lambda_l1=0.0`,
    `use_missing=true`, `zero_as_missing=false`, `deterministic=true`, `force_col_wise=true`다.
    class/sample weight는 사용하지 않으며 `Protocol`은 D-003에 따라 별도 범주 피처로 명시한다.
12. 최저 validation binary log loss와의 절대 차이가 **1e-6 이하**인 후보는 실질적 동률로 처리한다.
    동률이면 (1) 작은 `num_leaves`, (2) 큰 `min_data_in_leaf`, (3) 큰 `lambda_l2`,
    (4) 작은 `best_iteration`, (5) 앞선 `candidate_id` 순으로 선택한다.
13. 난수는 `seed=42`, `data_random_seed=42`, `feature_fraction_seed=42`,
    `bagging_seed=42`로 명시한다. 실제 LightGBM·Python 버전, OS, CPU/GPU, `num_threads`,
    전체 파라미터와 후보별 validation binary log loss·`best_iteration`, 최종 `candidate_id`,
    동률 규칙 적용 여부를 실행 manifest에 기록한다. `num_threads`는 실행 환경에 맞추되 기록한다.
14. **Early stopping은 `num_boost_round=3000`, `stopping_rounds=100`, `min_delta=1e-6`,
    `first_metric_only=true`로 고정한다.** Early stopping에는 내부 validation의 binary log loss만
    사용한다. 후보별 전체 validation loss history와 진단용 training loss history를 저장하되,
    training loss는 중단 조건에 관여시키지 않는다.
15. 후보의 validation loss가 NaN 또는 Infinity이면 해당 후보는 실패로 기록한다. 8개 후보가 모두
    실패하면 실험은 판정 불가다. 최종 선택 후보가 3000 iteration 상한 전에 early stopping되지
    않으면 상한 부족으로 보고 외부 test를 평가하지 않는다. 상한을 늘리는 경우 기존 결과를
    덮어쓰지 않고 새 실험 ID와 사전 스펙으로 실행한다.
16. **이진 판정 임계값은 0.5로 고정한다.** LightGBM의 공격 클래스 확률을 `p_attack`으로 저장하고,
    `p_attack >= 0.5`이면 `predicted_label=1`(공격), 아니면 0(정상)으로 판정한다. 정확히 0.5인
    동률은 공격으로 판정한다. validation 또는 외부 test에서 이 임계값을 최적화하지 않는다.
17. **AURC와 유보 순위에 사용할 `confidence`는 `max(p_attack, 1-p_attack)`으로 고정한다.**
    `is_error`는 `predicted_label != binary_label`로 정의한다. 모든 값을 반올림 없이 저장하고
    낮은 confidence부터 유보한다. `p_attack`이나 `confidence`가 NaN·Infinity 또는 허용 범위 밖이면
    기술적 판정 불가다. 확률 보정과 temperature scaling은 적용하지 않는다.
18. **경험적 AURC는 prefix risk의 산술평균으로 계산한다.** 외부 test `n`행을 `confidence`
    내림차순으로 정렬하고 상위 `k`개를 수용했을 때 `coverage=k/n`,
    `selective_risk=(상위 k개의 is_error 합)/k`로 정의한다. `k=1..n`의 `selective_risk`를
    산술평균한 값을 `aurc`로 둔다. 손실은 0/1 `is_error`이며 coverage 0의 risk를 임의로
    정의하거나 사다리꼴·사전 격자 적분을 사용하지 않는다.
19. **정확히 같은 float64 `confidence`의 내부 순서는 균등 무작위 순열의 기대값으로 처리한다.**
    반올림이나 tolerance로 새로운 tie를 만들지 않는다. 기존 prefix가 `k0`행·`E0`오류이고,
    tie 그룹이 `m`행·`q`오류이면 tie 안에서 `j=1..m`번째 prefix의 기대 risk를
    `(E0 + j*q/m)/(k0+j)`로 계산한다. 실제 셔플, 행 ID, 정답·오류 우선 tie-break는 사용하지 않는다.
20. AURC와 함께 `full_coverage_risk`, `random_aurc`, `oracle_aurc`를 반드시 보고한다.
    `random_aurc=full_coverage_risk`로 분석적으로 계산한다. `oracle_aurc`는 현재 오류 개수를
    고정한 채 모든 정답을 오류보다 먼저 수용하는 순위의 같은 prefix 공식으로 계산한다.
    정규화 AURC 계열은 주 지표로 추가하지 않는다.
21. **대표 `target_abstention_rate`는 0.01, 0.02, 0.05, 0.10으로 고정한다.** 유보율 0은
    `full_coverage_risk`로 별도 보고한다. AURC는 네 지점이 아니라 모든 prefix로 계산하며,
    운영 threshold 곡선은 모든 고유 confidence 경계를 저장한다. 결과를 본 뒤 대표 budget을
    추가하거나 가장 좋아 보이는 한 지점만 선택하지 않는다.
22. **각 budget은 초과할 수 없는 최대 검증 처리량이다.** 낮은 confidence의 완전한 tie 그룹부터
    누적해 목표 이하에서 가능한 가장 큰 집합을 유보한다. tie 그룹을 행 ID·정답·무작위 순서로
    일부만 자르지 않는다. `confidence_threshold=t`이면 양 끝을 포함하여 `confidence <= t`, 즉
    `abstention_band=[1-t,t]`를 적용한다.
23. 각 budget에 `target_abstention_rate`, `actual_abstention_rate`, 실제 유보 행 수, `coverage`,
    `confidence_threshold`, `abstention_band`, `budget_shortfall`, 다음 완전 tie 그룹까지 포함했을 때의
    유보율을 기록한다. 첫 tie 그룹부터 budget을 넘으면 실제 유보율은 0, threshold와 band는
    `null`로 두고 confidence 해상도 부족 사유를 기록한다.
24. Threshold 산출에는 해당 분석 test의 `confidence`와 사전 budget만 사용하고 label·`is_error`·
    성능지표는 사용하지 않는다. 주 분석과 행 단위 랜덤 민감도 분석은 같은 네 budget을 사용하되
    각 test confidence 분포에서 threshold를 따로 산출한다. Attempted·invalid-class 관찰군에는
    주 분석에서 구한 band를 변경 없이 적용하며 관찰군으로 threshold를 다시 산출하지 않는다.
25. **보조 지표는 M2 균형안으로 고정한다.** Coverage 100%의 외부 test 전체에서 `n_test`,
    confusion matrix(`tn`,`fp`,`fn`,`tp`), `full_coverage_risk`, FPR, FNR, `auroc`,
    `average_precision`, `binary_logloss`를 계산한다. 모호한 AUPRC 대신 scikit-learn의
    `average_precision_score` 정의를 사용하고 사다리꼴 PR-AUC는 산출하지 않는다.
26. 각 대표 budget에서 `selective_risk`, `error_capture_rate`, `selective_fpr`, `selective_fnr`,
    `residual_fpr`, `residual_fnr`, `benign_coverage`, `attack_coverage`를 계산한다.
    `selective_fpr=accepted_fp/accepted_benign`, `selective_fnr=accepted_fn/accepted_attack`이며,
    잔여 FPR/FNR은 같은 분자를 유보 전 전체 정상/공격 행 수로 나눈다. `error_capture_rate`는
    유보된 `is_error` 합을 coverage 100%의 전체 오류 수로 나눈다.
27. 지표 분모가 0이면 0으로 대체하지 않고 `null`과 `zero_denominator` 사유, 분자·분모 count를
    함께 기록한다. AUROC와 `average_precision`은 budget별 accepted subset에서 반복 계산하지 않는다.
28. 원래 `Label`별 전체-coverage 표에는 `n_test`, 정답·오류 수, 오류율과 공격 Label의 이진 recall
    또는 BENIGN specificity를 기록한다. Budget별 표에는 `n_test`, `n_accepted`, `n_abstained`,
    실제 유보율, accepted 오류 수·오류율을 기록한다. D-005에 따라 희소 클래스 수치를 근거로
    성능 주장을 하지 않는다.
29. 외부 test의 class-overlap 부분집합에는 행·Label 수, `p_attack`·`confidence` 분포,
    full-coverage 오류율, budget별 유보율·수용 행 수·`selective_risk`를 전체 test threshold 그대로
    적용해 보고한다. Attempted·invalid-class 관찰군에는 정답 기반 성능지표를 계산하지 않고 행 수,
    `p_attack`·`confidence`·`predicted_label` 분포와 주 분석 band 포함 수·비율만 기록한다.
    Attempted는 `Attempted Category`별로도 같은 분포를 낸다.
30. `p_attack`과 `confidence` 분포 요약은 min, p01, p05, p25, p50, p75, p95, p99, max로 고정한다.
    전체 test, 정답/오류, BENIGN/공격, class overlap, 두 관찰군에 적용한다. 모든 행의 원래 확률은
    별도 예측 파일에 보존한다. 행 단위 랜덤 민감도 분석에는 주 분석과 같은 계산식을 적용하되,
    class overlap과 관찰군의 핵심 보고는 주 분석을 기준으로 한다.
31. **이 서브실험에서는 bootstrap과 통계적 신뢰구간을 산출하지 않는다(U1).** 모델 재학습
    bootstrap, 행·그룹 bootstrap, p-value를 모두 범위 밖으로 둔다. 고정된 데이터·split·seed의
    점추정값과 정확한 분자·분모 count를 보고한다. 1/2/5/10% budget에서 효과가 일관되는지는
    운영점 변화에 대한 강건성으로 해석하되 표본추출 변동이나 신뢰구간으로 해석하지 않는다.
32. **최종 판정 기준은 S2 균형안으로 고정하며 주 분석만 사용한다.**
    `relative_aurc_improvement=(random_aurc-aurc)/random_aurc`,
    `error_enrichment=error_capture_rate/actual_abstention_rate`로 정의한다. 대표 budget이
    `actual_abstention_rate>0`, `error_enrichment>1`, `selective_risk<full_coverage_risk`를 모두
    만족하면 개선 지점으로 센다.
33. **성공**은 기술적으로 유효하고 전체-coverage 오류가 1건 이상이며 아래를 모두 만족할 때다.
    (1) `relative_aurc_improvement>=0.10`, (2) 5% 목표에서 `actual_abstention_rate>=0.04`,
    `error_enrichment>=2.0`, `selective_risk<full_coverage_risk`, (3) 네 budget 중 개선 지점 3개 이상.
34. **실패**는 기술적으로 유효하고 전체 오류가 존재하면서 다음 중 하나일 때다.
    `relative_aurc_improvement<=0`, 또는 5% 목표에서 실제 유보가 0, `error_enrichment<=1`,
    `selective_risk>=full_coverage_risk` 중 하나, 또는 개선 지점이 1개 이하. 결론은 “D-004 주 분할과
    현재 모델·confidence 조건에서 실질적인 유보 구간이 관찰되지 않았다”로 제한한다.
35. **과학적 판정 불가**는 기술적으로 유효하지만 성공과 실패 어느 쪽에도 들지 않는 약한 신호이거나
    전체-coverage 오류가 0건인 경우다. 예에는 AURC 상대 개선 0~10% 사이, 5% 오류 농축 1~2 사이,
    5% 실제 유보율 0~4% 사이, 개선 지점 정확히 2개가 포함된다.
36. **기술적 판정 불가**는 데이터 SHA·행 수·피처·split 검증 실패, 관찰군 혼입, 전처리 후 Infinity,
    학습 후보 전부 실패, 선택 후보의 iteration 상한 도달, 예측값 오류, 예측 ID 불일치, AURC 행 순서
    불변성 실패, `aurc<oracle_aurc`와 같은 산술 불가능 결과 등 측정 프로토콜이 무효인 경우다.
    행 단위 랜덤 민감도, 관찰군, class-overlap 부분집합 결과는 최종 판정을 바꾸지 않는다.

### 3. 근거

1. **사용자 확정(2026-09-14).** 학습 목적함수·early stopping·최종 평가 지표의 역할과 대안을
   비교한 뒤 위 권장안을 기본 프로토콜로 채택했다.
2. 이 서브실험의 질문은 분류 성능 경쟁이 아니라 confidence가 오류 가능성이 높은 flow를 선별하여
   유보할 수 있는지 확인하는 것이다. 따라서 전체 risk-coverage 관계를 평가하는 AURC가 최종 질문과
   직접 대응한다.
3. Binary log loss는 이진 확률 출력을 학습하는 LightGBM의 표준 목적함수이며, validation log loss는
   고정 분류 임계값 없이 전 표본의 확률 손실로 학습 길이를 선택할 수 있다.
4. LightGBM 공식 문서는 early stopping이 validation 지표의 개선 정체로 `best_iteration`을 정하며,
   여러 지표 중 첫 지표만 사용하려면 `first_metric_only=true`를 지정하도록 정의한다.
   출처: <https://lightgbm.readthedocs.io/en/v4.6.0/pythonapi/lightgbm.early_stopping.html>,
   <https://lightgbm.readthedocs.io/en/latest/Parameters.html>.
5. 방식별 비교와 기각 사유는 `docs/ml_training_evaluation_method_comparison.md`에 있다. 이 설명 문서는
   결정 정본이 아니며, 확정 상태는 이 D-006만 따른다.
6. 원본 전수 조사에서 `Flow Bytes/s`의 +Infinity는 5행이고 기존 NaN과 -Infinity는 0행이다.
   이 5행은 완전일치 1그룹이며 정상·공격 class overlap이 없다. 임의 상한이나 train 통계를
   추가하지 않고 계산 불능 rate를 결측으로 명시하는 것이 가장 작은 변환이다.
   출처: `docs/feature_inventory_2026-09-12.md` §2·§3-3,
   `reports/class_overlap/report.md` §3.
7. LightGBM은 기본적으로 NaN 결측 처리를 지원하며 `zero_as_missing=false`일 때 0은 결측으로
   취급하지 않는다. 출처: <https://lightgbm.readthedocs.io/en/v4.5.0/Advanced-Topics.html>.
8. **사용자 확정(2026-09-14).** 내부 validation의 안정성을 우선하여 80:20보다 큰 validation을
   제공하는 75:25를 선택했다. 외부 train 1,447,147행 기준 목표 규모는 내부 train 약 108.5만,
   validation 약 36.2만 행이며, 최종 재학습은 외부 train 전체를 사용하므로 validation 행이
   영구적으로 학습에서 빠지지 않는다.
9. 이 프로젝트는 내부 교차검증과 seed 반복을 하지 않으므로 한 번의 validation에서
   `best_iteration`을 정해야 한다. 그룹을 보존한 75:25 분할은 이 단일 validation의 변동을
   줄이면서도 최초 fit에 100만 행 이상을 남긴다.
10. **사용자 확정(2026-09-14).** 부적절한 단일 설정으로 인한 음성 결론 위험을 줄이되 모델 성능
    경쟁으로 범위를 확장하지 않도록 최대 8개 사전 격자를 채택했다. 제한된 후보를 내부 validation
    log loss로만 선택하면 외부 test 독립성을 유지하면서 기준 모델의 명백한 과소·과대적합 위험을
    완화할 수 있다.
11. **사용자 확정(2026-09-14).** LightGBM 기본 구조에 가까운 기준점과 규제 대안을 함께 비교하기
    위해 `num_leaves={31,63}`, `min_data_in_leaf={20,200}`, `lambda_l2={0,1}`의 완전 격자를
    선택했다. 세 축만 변화시켜 후보 차이를 해석할 수 있고 8개 상한을 지킨다.
12. `learning_rate=0.05`는 early stopping의 iteration 변화를 세밀하게 관찰하기 위한 공통값이며,
    feature·row sampling을 끄고 결정론 설정과 seed를 명시하여 단일 seed 정책에서 후보 간 무작위
    차이를 최소화한다. LightGBM 파라미터 정의 출처:
    <https://lightgbm.readthedocs.io/en/latest/Parameters.html>.
13. **사용자 확정(2026-09-14).** 약 36만 행의 내부 validation과 `learning_rate=0.05`에서 안정성과
    8개 후보의 실행 비용을 균형 있게 유지하도록 3000/100/1e-6 조합을 채택했다. `min_delta`는
    후보의 실질적 동률 허용치와 같은 크기로 두어 수치적 잡음을 개선으로 계속 추적하지 않는다.
14. LightGBM 공식 문서는 validation 지표가 `min_delta` 이상 개선되지 않은 상태가
    `stopping_rounds`만큼 이어지면 학습을 중단하고 최적 iteration을 `best_iteration`에 저장한다고
    정의한다. 출처: <https://lightgbm.readthedocs.io/en/v4.6.0/pythonapi/lightgbm.early_stopping.html>.
15. **사용자 확정(2026-09-14).** 무가중 binary log loss와 미정의 상태인 오탐·미탐 비용비에
    불필요한 추가 선택을 만들지 않도록 판정 임계값 0.5를 채택했다. `max(p,1-p)`는 정상과 공격
    양쪽의 확신을 대칭적으로 처리하며 확률 margin과 동일한 순위를 더 직접적으로 표현한다.
16. AURC의 변환 불변성은 `p_attack`에 대한 임의의 단조변환이 아니라, 먼저 확정한
    `confidence=max(p_attack,1-p_attack)`의 순위와 동률을 보존하는 엄격한 단조변환에만 적용된다.
17. **사용자 확정(2026-09-14).** 모든 prefix risk의 평균은 coverage 0의 risk나 임의 격자 없이
    경험적 risk-coverage를 정의한다. LightGBM의 반복 확률에서 행 순서가 AURC를 바꾸지 않도록
    tie 내부 무작위 순열의 기댓값을 분석적으로 사용한다.
18. Raw AURC는 base error와 함께 해석해야 하므로 유보 없음, 무작위 순위, 현재 오류 수에서의
    이론적 최선이라는 세 기준선을 함께 둔다. AURC의 유한 표본 추정에 관한 근거:
    Zhou et al., *A Novel Characterization of the Population Area Under the Risk Coverage Curve
    (AURC) and Rates of Finite Sample Estimators*, ICML 2025,
    <https://proceedings.mlr.press/v267/zhou25y.html>.
19. **사용자 확정(2026-09-14).** 소수 flow만 심층 검증한다는 연구 범위를 유지하면서 초기·중간·상한
    효과를 보기 위해 1/2/5/10%를 채택했다. Budget을 최대 처리량으로 해석하므로 동일 confidence를
    임의로 분할해 정확한 비율을 맞추기보다 완전 tie 그룹을 유지하고 실제 유보율을 함께 보고한다.
20. **사용자 확정(2026-09-14).** 유보 효과를 오류 선별과 처리량 양쪽에서 해석하되 budget마다
    모든 순위 지표를 반복하는 과잉 보고를 피하도록 M2를 채택했다. 선택적 FPR/FNR만으로는 유보로
    빠진 클래스 비율을 숨길 수 있으므로 전체 분모의 잔여 오류율과 클래스별 coverage를 병기한다.
21. **사용자 확정(2026-09-14).** 본 작업은 빠른 착수와 존재 확인을 목적으로 하는 subexperiment이므로
    구현·계산량을 늘리는 bootstrap보다 U1을 선택했다. 외부 test 482,382행의 고정 benchmark
    점추정, 네 budget의 추세, D-004 주 분석과 낙관적 민감도 분석의 차이로 필요한 진단을 수행한다.
22. **사용자 확정(2026-09-14).** 통계적 유의성 대신 무작위보다 10% 나은 전체 순위, 5% budget의
    2배 오류 농축, 네 운영점 중 세 곳의 일관된 개선을 요구하는 S2를 채택했다. 작은 양의 차이를
    성공으로 과장하지 않고 명확한 무효·실패와 경계 신호를 분리한다.

### 4. 결과적으로 따라오는 영향

- 외부 test는 학습, `best_iteration` 선택, 하이퍼파라미터 선택에 사용하지 않는다.
- 내부 validation에서 `best_iteration`을 고른 뒤 외부 train 전체로 그 iteration 수만큼 재학습하고,
  완성된 모델을 외부 test에서 한 번 평가하는 구조가 필요하다.
- 기본 실험의 클래스 불균형 처리는 가중치가 아니라 원자료 분포 보존으로 고정된다.
- Accuracy나 F1이 높더라도 AURC를 대신하여 성공을 선언할 수 없다.
- Brier와 ECE는 D-004에 따라 계속 범위 밖이다.
- `Flow Bytes/s`의 무한대 5행은 모집단과 D-004 split에서 유지되며, 재학습과 test에도 같은
  결정론적 변환을 적용한다. 전처리로 인해 행 수가 달라지면 학습을 시작하지 않는다.
- 내부 분할에서 완전일치 그룹 교차가 발생하거나 원래 `Label` 하나라도 한쪽에서 소멸하면
  해당 분할은 무효이며 학습을 시작하지 않는다.
- 내부 validation은 `best_iteration`과, 추후 허용할 경우 하이퍼파라미터 선택에만 사용할 수 있다.
  외부 test 결과를 보고 `best_iteration`을 변경할 수 없다.
- 주 분석에서 선택한 최종 하이퍼파라미터는 D-004의 행 단위 랜덤 민감도 분석에도 그대로 사용한다.
  민감도 분석에 맞춰 재선택하지 않는다.
- 8개 후보 전부의 설정과 내부 validation 결과를 보존한다. 선택된 후보만 남기거나 실행 후 격자를
  변경할 수 없다.
- 최종 후보가 iteration 상한에 도달하면 후보 선택이 완결되지 않은 것이므로 외부 test를 열지 않는다.
  이는 모델 성능 실패가 아니라 학습 프로토콜의 기술적 판정 불가다.
- Coverage 100%의 기본 분류 결과는 고정 임계값 0.5로 산출하고, 유보 분석은 같은 예측의
  `confidence` 순서만 변화시킨다. 임계값 최적화가 결과에 섞이지 않는다.
- AURC 구현은 입력 행 순서와 tie 내부 라벨 배열에 불변이어야 한다. 행 순서를 바꾼 검증에서 값이
  달라지면 외부 test 해석을 중단한다.
- 대표 budget threshold는 test label을 사용한 최적점이 아니며 배포 threshold로 주장하지 않는다.
  실제 배포 threshold 결정은 이 서브실험 범위 밖이다.
- 보조 지표 표에는 비율만 두지 않고 모든 핵심 분자·분모 count를 함께 저장한다. 관찰군에는
  신뢰할 수 있는 `binary_label`이 없으므로 정답 기반 지표를 만들지 않는다.
- 신뢰구간과 통계적 유의성을 주장하지 않는다. Budget별 추세는 operating-point 강건성이고,
  행 단위 랜덤 split 비교는 중복 누수에 대한 구조적 민감도이지 표본추출 불확실성이 아니다.
- 최종 성공·실패·판정불가 상태는 외부 test를 열기 전에 실험 스펙에 복제하지 않고 D-006을
  참조하여 고정한다. 실행 후 기준 수치나 부등호를 변경하지 않는다.
